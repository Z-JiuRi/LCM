## 1. 设计目标和非目标

第一版代码要回答“给相同执行器和证据预算，不同决策策略如何影响安全进展、业务价值和成本”，而不是重新实现无线神经网络或先搭完整 O-RAN。原型首先需要一个可回放、可故障注入、可隔离真值的生命周期环境。无线模型、信道仿真和 LLM 应通过窄接口接入。

代码分成四类责任：

1. **领域核心**：manifest、状态、证据、预算、提案、状态转移和审计事件，不依赖 LLM 或具体无线仿真器。
2. **确定性执行面**：验证动作、占用资源、推进事务、拒绝过期证据、注入故障和执行回退。
3. **决策策略**：规则、统计监测、固定工作流、主动测量策略及可选 LLM planner；只读其授权的观测并提出动作。
4. **适配与评价**：数据集/模型/仿真工具适配器，以及不向 planner 暴露隐藏真值的独立 evaluator。

第一版不训练通用 Agent、不重写 OAI、不把第三方无线模型复制进核心包，也不把文本输出当成事务执行接口。

## 3. 模块边界和依赖方向

```text
adapters ──────┐
policies ───────┼──> domain contracts
simulator ─────┤
runtime ────────┘

evaluator <──── simulator event stream + private truth
```

依赖规则：

- `domain/` 只依赖 Python 标准库和项目 schema；不导入 PyTorch、LangChain、ns-3 或 Sionna。
- `policies/` 只接收 `ObservationView`，返回 schema-valid 的 `ActionProposal`；不能访问 evaluator 私有数据、任意路径或原始外部对象。
- `runtime/` 是动作放行的唯一入口。任何策略都不能直接激活模型、改变活动 epoch、绕过预算或改写审计日志。
- `adapters/` 将第三方输入转换为项目自己的数据契约；第三方依赖按 adapter 单独安装和锁版本。
- `evaluation/` 从独立 event log 和隐藏真值计算结果。提示词、RAG 和工具返回均不得包含隐藏状态。
- `simulator/` 使用显式的仿真时间；LLM/API 调用的墙钟时延要记录并可配置是否推进无线环境。

测试用依赖图检查或 import-lint，避免 `domain` 反向依赖 `adapters` / `evaluation`。

## 4. 领域接口草案

### 4.1 Planner 接口

```python
class Planner(Protocol):
    def propose(self, observation: ObservationView) -> ActionProposal: ...
```

`ObservationView` 只含：当前公开状态、可见证据、候选动作、各工具成本、剩余预算和动作约束。每个策略都使用同一接口和同一 schema；LLM 输出先解析，再交由 `DeterministicExecutor.validate()`，解析失败视为策略失败，不触发隐式默认动作。

### 4.2 主要对象

| 对象 | 最小字段 | 说明 |
|---|---|---|
| `FunctionManifest` | function ID、digest、输入/输出契约、radio config digest、适用域、资源需求、fallback | 单侧模型功能；字段按用例扩展 |
| `PairManifest` | encoder/decoder digest、latent schema、量化/预处理、feedback config | 仅双侧 CSI 用例需要，不强加给波束主用例 |
| `EvidenceItem` | subject、function/config epoch、source、method、observed_at、arrived_at、expires_at、uncertainty、cost、permitted_use | 明确证据生成时刻和消费时刻 |
| `RuntimeState` | active manifest/epoch、资源余量、pending transaction、fallback status | 执行器唯一权威状态 |
| `ActionProposal` | action type、target、evidence refs、preconditions、estimated cost、fallback target | planner 提案，不是执行命令 |
| `ActionResult` | decision、reason code、event ID、new state version | `COMMIT/HOLD/RETRY/REJECT/ROLLBACK` 等结果 |
| `EpisodeEvent` | sequence、sim time、wall time、actor、event type、refs、result | append-only，可重放和审计 |

只用 manifest 中的不可变摘要/哈希绑定模型权重、配置与预处理。可变“名称”不能作为兼容性证明。`config_epoch` 变化时，依赖旧 epoch 的证据默认失效，除非某个证据类型在实验中明确定义了可迁移规则。

### 4.3 工具最小集合

第一版先实现确定性工具：`query_public_state`、`request_measurement`、`evaluate_candidate`、`check_compatibility`、`prepare_candidate`、`commit_activation`、`rollback`、`get_event_status`。每个工具声明权限、输入 schema、成本模型、超时、幂等键及可注入故障。工具结果引用结构化对象，不直接回传大矩阵或自由文本。

适配器可以逐渐实现：

| 接口 | 第一版实现 | 后续候选 |
|---|---|---|
| `ChannelProvider` | 固定轨迹/合成 channel trace | DeepMIMO 或 QuaDRiGa |
| `ModelEvaluator` | CsiNet only-test / beam top-K 指标 | Sionna PHY 链路 KPI |
| `SystemSimulator` | 有状态 lifecycle environment | 5G-LENA；再评估 O-RAN 扩展 |
| `LLMProvider` | 空实现，测试不需要外部模型 | 可替换 provider，固定模型/版本/temperature |
| `RANAdapter` | 不实现 | 稳定后再考虑 OAI RFsim + FlexRIC |

DeepMIMO 的[官方文档](https://www.deepmimo.net/docs/)应作为候选场景/信道适配器的技术入口，不侵入核心状态机。Sionna 的[官方仓库文档](https://github.com/NVlabs/sionna)区分 RT、PHY 和 SYS；当前 PHY/SYS 安装要求 Python 3.11+ 与 PyTorch 2.9+。因此建议项目 core 以 Python 3.11 为最低版本，同时把 Sionna 放在可选 extra/容器环境，而不是 Phase 0 的硬依赖。[5G-LENA 官方发布说明](https://cttc-lena.gitlab.io/nr/html/md__2builds_2cttc-lena_2nr_2_r_e_l_e_a_s_e___n_o_t_e_s.html)在 2026-10-20 查阅时列出 NR-v5.1 稳定发布、v5.2 开发中且 v5.1 对应 ns-3.48；如果后续选用，应固定兼容版本并独立核查许可证及接口边界。版本信息应在实际开始集成时重新核验。

## 5. 状态机与安全责任

第一版通用状态机不等同于具体协议已定稿：

```text
IDLE
  -> EVIDENCE_PENDING
  -> EVALUATING
  -> PREPARING
  -> READY
  -> COMMITTING
  -> ACTIVE
  -> MONITORING
  -> ACTIVE | ROLLBACK_PENDING | FALLBACK
```

任何失败或未知提交结果进入可查询的 `PENDING_RECOVERY`，不能让 planner 根据对话记忆猜测最终状态。事务至少有稳定 `transaction_id`、目标 epoch、幂等键、准备方集合、资源预留记录和持久事件。单侧功能可以用本地原子替换/版本切换；双侧配对需额外处理部分激活和 ACK 丢失，不能用单侧事务语义替代。

执行前验证顺序：schema/授权 → 证据新鲜度与用途 → subject/config/function 绑定 → 当前资源与预留冲突 → 兼容性 → 前置状态版本 → 执行动作。最后一次检查和动作提交间若相关状态可能变化，应由锁、compare-and-swap 版本或短期 reservation 约束 TOCTOU 窗口。

Hard invariants 应写成可执行检查：不兼容动作不放行；过期/错 epoch 证据不授权新动作；重复事务不重复扣预算或重复安装；崩溃后可从事件日志恢复事务状态；UE 资源 reservation 不超售；fallback 始终可查询且有明确定义。Agent 文本和规则说明不是不变量的证明。

## 6. 文件、配置和实验产物约定

- 配置文件定义策略、成本、时钟、故障率、场景 split 与 simulator；schema 有版本号和默认拒绝未知字段。
- episode 输入写 JSONL，配置与小型状态直接内嵌，CSI/模型权重使用内容哈希引用，不复制进日志。
- 事件采用 append-only JSONL；每次 run 有 manifest，包含 Git SHA、依赖 lock hash、配置 hash、数据/模型哈希、随机种子和运行时版本。
- 真值文件与 agent-view 分开存放；评价阶段通过 ID 关联，不将 evaluator private labels 放在策略可读目录。
- `results/`、`artifacts/`、下载数据和第三方克隆默认忽略；提交数据 manifest、生成说明和最小小样本 fixture。
- 输出 CSV/Parquet 应可由 episode ID + seed 回溯到原始事件；论文图表脚本从这些固定表格读取，不手工改数字。

### 6.1 单 episode 输入

至少固定：episode/scenario ID、初始状态、候选 manifest refs、可见 KPI、可见 evidence、设备 profile、工具动作预算、时间预算、故障日程、隐藏真值 ref 和确定性随机种子。Agent 只看到前八项中的授权字段，不看到故障日程或真值。

### 6.2 单 episode 输出

保存：动作序列、每次工具输入/输出引用、花费的每类预算、状态变更、过期/拒绝原因、真实生效时间、恢复状态、运行后 KPI、planner token/API/墙钟成本及 evaluator 标签。不能只保存最终动作和成功率。

## 7. 第三方代码的采用边界

| 本地代码 | 可借鉴/使用 | 不应默认做什么 |
|---|---|---|
| AgentSpec (`相关工作/codes/P18_AgentSpec`) | 规则可执行、动作前检查的对照思路 | 把 LangChain 依赖或其通用策略语言设为核心依赖 |
| WirelessAgent / WirelessAgent++ | 无线工具编排、workflow 与 benchmark 思路 | 把其网络切片成绩当作 LCM 证据；照搬重型 workflow search 到 Phase 0 |
| AgentRAN + OAI fork | 软件 RAN 的 telemetry/control 接口案例 | 把 InfluxDB shim 说成正式 E2，或第一阶段依赖整套 OAI 镜像 |
| CsiNet | 固定模型候选、only-test 与 reference 数据结构线索 | 把 2018 Python/Keras/TensorFlow 环境直接装入新 core；声称已经复现 |
| DeepBeam / DeepSense / Neural Positioning / DeepRx | 不同无线用例和数据处理案例 | 假设所有仓库是论文作者官方实现、许可证一致或能在一个 Python 环境运行 |

所有第三方代码只通过 adapter 或独立环境调用。固定 commit/tag、许可证、模型权重、数据访问条件和预处理版本。当前代码仓库的存在和 README 报告的结果不等于本项目已经安装、运行或验证该结果。

## 8. 建议实现阶段与完成门槛

| 阶段 | 实现内容 | 通过条件 | 暂不做 |
|---|---|---|---|
| C0 核心闭环 | domain schema、episode replay、确定性状态机、事件日志、私有 evaluator、规则策略 | 正常/拒绝/超时/重试/回退轨迹可重复回放；基本安全性质有单元与故障测试 | LLM、真实 channel、OAI |
| C1 证据预算 | measurement tool、cost ledger、过期/epoch 绑定、统计基线、主动证据策略 | 同一 episode 下 cost 与风险可比较；重放确定性；持出场景防泄漏 | 端到端无线 KPI claim |
| C2 无线主用例 | 固定波束模型/测量或 CSI only-test adapter；模型 manifest；后验收 | 数据契约、场景划分、模型行为可复现，模型变化能影响业务效用函数 | 混合多个仿真器 |
| C3 规划器比较 | workflow、单网络侧 LLM + 确定性 Runtime；固定提示/模型/预算 | LLM 对非 LLM 的增量收益含成本，安全 gate 对所有基线一致 | UE LLM |
| C4 CSI 双侧事务 | PairManifest、兼容性、PREPARE/READY/COMMIT/ACK、丢包/崩溃恢复 | 部分提交、重放、并发和 epoch 不一致有可测试状态和恢复条件 | 把 CSI 专例强加给单侧用例 |
| C5 系统/软件 RAN | 5G-LENA 或 OAI RFsim 选一条主路径；适配器和时钟映射 | KPI 映射、动作生效与开销有验证；版本固定 | 仅为图示而接多仿真器 |

每阶段先冻结接口和契约，只有通过前一阶段的研究决策门才新增依赖。阶段细节和实验判据见[实验方案](实验方案.md)。
