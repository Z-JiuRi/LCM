### 摘要（Executive Summary）

**核心判断**：AutoML 正从“自动搜索最优模型配置的优化系统”转向“理解需求、制定策略、执行并验证端到端机器学习工作的智能闭环”。但这不是简单用大模型替代贝叶斯优化；在多数受约束的真实工程场景中，更可靠的技术路线是 **LLM/Agent 负责开放世界规划与异常处理，成熟 AutoML 内核负责受控、可复现的模型搜索与训练，确定性评估器负责裁决，人工审批守住高风险边界**。

最重要的发现：

1. **传统 AutoML 已形成扎实基础**。Auto-WEKA 将算法选择和超参数优化组合成 CASH 问题；auto-sklearn 引入元学习与集成；Hyperband/BOHB 解决预算调度；AutoGluon 强调 bagging/stacking/多模型组合；FLAML 强调低成本搜索；AMLB 提供跨框架可复现基准。上述思想是 Agentic AutoML 的“内核”，不是被淘汰的旧路线。[R01]–[R12]
2. **Agentic AutoML 不是单一方法，而是一族系统**。AutoML-Agent 关注任务描述到部署的全流程多智能体分工；DS-Agent 关注基于案例的经验迁移；AIDE 将 ML 工程表示为代码空间上的树搜索；R&D-Agent 将研究假设与代码实现拆开；ML-Master 将并行探索与选择性记忆融合。它们的目标与实验环境并不相同，不能仅凭某个单独的“成功率”排序。[R20]–[R27]
3. **2026 年的重要变化是从“提示词驱动”走向“训练型 Agent”**。ICML 2026 的 ML-Agent 用交互式实验数据、逐步强化学习和专门的奖励建模训练约 7B 模型；DeepAnalyze 利用课程式训练与真实环境交互学习复杂数据科学能力。这意味着未来既要研究**搜索空间和调度**，也要研究**agent policy 的训练、经验表示和泛化**。[R28]–[R29]
4. **评估难于演示**。MLE-bench 原始论文包含 75 项 Kaggle 相关竞赛；2024 年原始论文中的 AIDE + o1-preview 铜牌及以上比例为 16.9%，而官方项目在 2026 年公开的榜单中出现 60% 以上的提交结果。不同模型、搜索预算、实验日期、复现透明度和榜单版本差异很大，不应把这些数字理解为同等严格条件下的增长曲线。[R30]–[R34]
5. **生产级系统的瓶颈在“验证与治理”**：数据泄漏、验证集过拟合、不一致的随机种子、GPU/CPU 资源滥用、代码执行安全、外部依赖、不可解释的搜索选择，以及模型部署后的数据漂移，比模型能否生成几行训练代码更有决定性。[R10], [R30]–[R34]
6. **最值得优先验证的架构**：`Task/Policy Intake → Data Profiler → Plan & Retrieval Agent → Search Orchestrator → AutoML/HPO Engine → Evaluator/Guardrails → Memory & Experiment Store → Human Approval → Deployment & Monitoring`。第一阶段不需要多达十几个 agent，而应先用单 orchestrator + 工具链建立严格实验闭环。

**专题增补及勘误（2026-10-22）**：[第 21 章](../AutoResearch/概念边界与详细对照.md#s21)基于 Karpathy 初版开展三者比较，其 `autoresearch` 能力描述主要适用于早期固定实验范例，**不可推广为整个生态的能力上限**。新增 **[第 22 章](../AutoResearch/生态谱系与项目分组.md#s22)《2026 年 Autoresearch 生态全景》**，系统补充 oh-my-pi、pi-autoresearch、通用优化 harness、科研全流程、并行多 Agent、跨研究共享记忆、自改进以及可信科研评测，汇总原始论文、源码项目及作者博客，并修订三者边界。

**一句话结论**：Agent 提升“做什么、为何这么做、失败后如何调整”的智能化程度；AutoML 优化器提升“在已定义且受约束的候选空间中，如何高效寻找优秀模型”的可靠性；验证与数据治理确保找到的结果真实可用。

## 1. 研究范围、方法与证据层级

<a id="s1-1"></a>

### 1.1 具体研究问题

本报告系统回答以下问题：

- **RQ1 范畴**：AutoML、AutoDL、NAS、HPO、MLOps 自动化、Data Science Agent 与 AI Scientist 有何区别？
- **RQ2 算法**：传统 AutoML 的搜索空间、目标函数、优化策略、早停和集成技术为何有效？
- **RQ3 系统**：Agent 能在哪些环节扩大 AutoML 的自动化边界？Agent 是规划器、执行器、算法选择器，还是可通过强化学习训练的策略？
- **RQ4 性能**：AutoML-Agent、MLAgentBench、AIDE、DS-Agent、AutoKaggle、MLE-bench、ML-Master、ML-Agent 和 DeepAnalyze 究竟证明了什么？
- **RQ5 生产**：能否把 Agent 接在 AutoGluon/FLAML/Optuna 等工具上，构造可控的闭环系统？
- **RQ6 科研**：哪些难点仍没有被现有论文扎实解决，可以形成新研究贡献？

### 1.2 纳入与排除条件

**纳入**：同行评审论文与经典出版物；高相关预印本；官方评测说明；代表性项目实现与文档；AutoML 核心算法、机器学习工程 agent、数据科学 agent、训练型 agent、可复现基准。**排除或仅作背景**：只把 ChatGPT 包装成聊天界面的项目、没有可验证评价协议的营销榜单、没有明确 ML 任务的通用办公 Agent、只讨论语言模型提示词却未执行 ML 实验的文章。

## 0. 结论先行

1. **AutoML 的技术内核不是"自动选模型"，而是在预算约束下对结构化搜索空间做序列决策**。真正稳定起作用的三件事是：多保真度/预算控制（Hyperband、BOHB、FLAML 的代价感知搜索）、元学习热启动（auto-sklearn 2.0、AgentHPO 系）、以及集成与后处理（AutoGluon 的 stacking 往往比搜索算法更决定结果）。
2. **"Agent for AutoML"已经分化成五种不同范式**，混为一谈是当前最常见的误读：LLM 当搜索算子、LLM 做代码级管线搜索、LLM 生成搜索空间交给经典优化器、LLM 当评估/审计者、端到端 AI 科学家。它们的证据强度和失败模式完全不同。
3. **2026 年出现了明确的反证潮**，且直接针对"agent 有必要吗"这个提问方式：
   - 预算匹配 + 多样本协议下，LLM 的 HPO 增益主要来自**热启动的默认配置**（88.7% mean best-CV），LLM 自身提议对 held-out test 是 −0.01pp（$p = 0.92$）〔2606.21641〕；
   - 固定预算下 CMA-ES/TPE **稳定优于** LLM agent，且"避免 OOM"比"搜索多样性"更重要〔2603.24647〕；
   - 同 backbone、同时间预算下，复杂 harness **不优于**最小 harness 的单次 coding agent〔2609.40303〕；
   - 短预算 AutoML 对比的"胜出"可完全由协议缺陷制造（测试集选型 + 预算未真正执行），修正后胜率 59.4%→34.3% 且不再显著〔2608.07303〕。
4. **最被低估、也最可能站得住的分工是"LLM 造搜索空间，经典优化器做搜索"**：agent 为模块化管线写候选实现，再由 HPO 联合优化，45 个表格数据集上平均相对增益 0.6%（小中型回归 2.0%）〔2609.16309〕；AgentNAS 用同一机制把开放式 LLM 设计与有界 NAS 搜索拼接〔2607.07984〕。
5. **评估正在从"结果级"转向"决策级"与"方法学正确性"**：目前没有任何 agentic AutoML 系统报告结构化的决策级指标〔2602.22442〕；只测下游精度会掩盖数据泄漏和错误验证〔2610.14115〕；"注入相关任务洞见"本身就是未受控的泄漏渠道〔2610.04927〕。
6. **对 LCMAgent 的直接含义**：AutoML 是与本项目最近的"预算化序列决策"抽象，但它默认三件事——可反复试跑、目标单一、动作可回退——这三条在无线侧全部不成立。因此可迁移的是**协议与评估纪律**，不可迁移的是**搜索算法本身**。
7. **一个已被量化的时间尺度警告**：纠正类生命周期命令加入 0→40 控制步延迟后，stability-gated blending 相对硬切换的优势从 $47.02 - 7.57 = 39.45$ violation-steps 骤降到 $47.02 - 44.38 = 2.64$〔2609.14517〕。这为"慢速规划 / 快速执行"分层提供了外部依据，也说明 LCMAgent 的性能主张必须在**有控制延迟**的条件下测。

## 1. AutoML 的问题结构

综合 `1908.00709`、`1904.12054`、`2010.10777`、`2112.09245` 的划分，AutoML 实际由四个可分离的子问题组成。区分它们很重要，因为"agent for AutoML"在四层上的可行性完全不同。

| 层 | 问题 | 经典解法 | 空间性质 | LLM/agent 的可行性 |
|---|---|---|---|---|
| L1 评估协议 | 用多少预算、什么划分、多少次重复来判定"更好" | 交叉验证、留出、多保真度 | 非搜索 | 低（属于纪律而非智能） |
| L2 超参/配置搜索 | 在给定空间内最小化验证损失 | BO/TPE、Hyperband/BOHB、CMA-ES | 连续/混合、低维 | **低–中**（有反证） |
| L3 搜索空间与管线结构 | 空间本身从哪来：算子集、模块、拓扑 | 手工工程、NAS 超网、元学习先验 | 离散、开放 | **高**（当前最成立的用法） |
| L4 任务理解与验证 | 读懂任务、判断方案是否可信、定位失效 | 人工专家 | 语义 | 高，但测量困难 |

**关键事实**：AutoML 文献的绝大多数增益叙事集中在 L2/L3，而 2026 年的反证正好打在 L2 上（§4）。L4 是 agent 唯一没有遇到强反证的地方，但也正是**最难测量**的地方——这解释了 §5 中决策级评估为何成为新的研究焦点。

## 9. 风险与不确定性

- **证据深度**：全部为摘要级核验。`2606.21641`、`2603.24647`、`2609.40303` 的关键数字（88.7%、−0.01pp、$p = 0.92$、CMA-ES 一致性优势）来自摘要，未核对实验章节与附录。
- **发表偏倚**：arXiv 上 AutoML 负结果极少，本次仅命中 4 篇。反证的真实比例高于文献表面比例，但方向与量级不可由本次检索估计。
- **时效性**：2026 年条目引用数多为 0，不能用作质量信号；其中部分可能仍在评审中，venue 标注来自 arXiv 注释或 OpenAlex 记录，可能与最终发表版本不一致（AutoML-Agent 的 ICML 2025、MARS 的 ICML 2026、I-MCTS 的 EACL 2026 Findings 均属此类）。
- **域外推断**：把 AutoML/agentic AutoML 的结论迁移到无线生命周期管理属于**类比推断**，不是已验证结论。[§7.1](../LCMAgent/AutoML借鉴与迁移边界.md#q7-1) 的"可直接迁移"指机制可信，不指在本项目场景中已测。
- **未覆盖**：SIGMOD/VLDB/KDD 工业 track 的系统实现细节、AutoML 的可解释性与公平性分支（`FairAutoML`、`human-centered AutoML` 等只在检索中偶现，未系统纳入）。
