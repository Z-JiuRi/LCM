# 本机 1 km 全量 RT 耗时：基于现有 smoke 的粗估

2026-10-27。仅使用已有测量做外推，本轮没有为估时启动新RT，更没有跑全城。此估算不是性能保证或收敛认证。

## 已知条件

- 本机实测：Apple M1 Pro，8 CPU核，16 GiB统一内存；当前RT使用Metal。
- 完整1km几何：29726UE、18扇区，共535068个扇区—UE链路。
- 当前生产候选配置：深度7、绕射/漫散射开启、32RX/批、100000 samples/source、候选容量200000。
- 需要 `ceil(29726/32)×18 = 16722` 次求解器调用。
- 已完成的[smoke结果](<../../data/csi/smoke-source-informed-final/smoke-summary.json>)：8UE×2扇区，2RX/批、2000 samples/source、容量20000；完整城市场景但极低路径预算。
- 两扇区的solve合计1.16211秒、8次调用，平均0.14526秒/调用；JIT缓存已热。这不包括构建、全部传输/写出/导出，也不能将smoke总时长按UE数直接乘。

## 可解释的外推包络

把射线预算近似线性放大50倍，先忽略接收批增加的成本：

$$T_A=0.14526\times16722\times50\approx33.7\ \mathrm{hours}.$$

这是RX分摊极理想的情景，不是严格下界，也不是预计完成时间。

若增加2→32个RX的成本也近似线性（16倍）：

$$T_B=T_A\times16\approx22.5\ \mathrm{days}.$$

这也不是严格上界。确定性候选处理中存在按RX数放大的工作数组；同时GPU并行/固定开销又可能使部分工作被分摊。漫散射返回路径增加、候选截断、内存换页、CPU相干合成和磁盘压缩均会破坏简单线性假设。

**目前只能给“数天到数周”这一量级；如果安排机器，建议按1–3周预留，而不是按几小时。**这是风险预留，不是由2点基准拟合出的统计预测。路径更丰富或16GiB内存不足时可能更久甚至OOM；如果更小chunk才能运行，总调用数又会改变。

## 影响最大的未知量

1. 当前低预算smoke有一半UE未找到路径，高预算下每个链路的路径数可能明显增长。
2. 原始路径保存和压缩仍消耗CPU/磁盘；仅全扇区CFR约8.16GiB，服务/地块输出后约9.1GiB，路径另计。
3. 统一内存只有16GiB，显存与主机共享；不能保证默认32RX×100000射线在深度7时具备足够余量。
4. 笔记本持续热负载、其他应用和休眠会影响实际时间；没有测长时间稳态。
5. 当前没有断点续跑，长跑中断成本高。

## 如果以后需要收窄估计

先明确授权一个受限的代表性计时：少量LOS/转角/深NLOS、生产射线预算、生产chunk，记录峰值内存和每批耗时，至少分别区分JIT首批与热批。不能拿最低预算、只有2RX的调用去承诺整城速度。此时仍无需先跑完整城市。

服务器3×A6000可以并行扇区并有更充足显存，但本轮没有CUDA测速，因此也不给未经测量的加速倍数。
