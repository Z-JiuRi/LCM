### 21.14 将三者放在同一个预算下公平评测：建议实验协议

简单比较“最终最优分数”会系统性偏袒能投入更多搜索、Token、重试和研究技巧的一方。建议采用 **三种预算视角同时报告**：

**A. 统一 GPU 训练小时**：便于与 HPO 论文比较，但未计入 LLM 和 CPU 预算，不能当完整 TCO。  
**B. 统一实际美元成本**：GPU、CPU、存储、API tokens、环境准备和失败重试都计价。  
**C. 统一 wall-clock 时间**：在相同并行配额下，从任务进入系统到最终产物交付的总历时。

建议至少有以下对照组：

| 组别 | 搜索空间 | 策略 | 作用 |
|---|---|---|---|
| B0 | 固定 HP | Random Search | 排除“随便试就能进步”的效应 |
| B1 | 同 B0 | TPE/SMAC/CMA-ES | 传统 AutoML 强基线 |
| B2 | 同 B0 | LLM 提议下一组 HP | 检查纯语言模型数值搜索 |
| B3 | 同 B0 | LLM + 优化器状态（Centaur 式） | 衡量算法和语义策略互补性 |
| B4 | 固定编辑文件/操作集合 | 单 Agent 改代码 | 衡量开放代码编辑价值 |
| B5 | 同 B4 | 单 Agent + 结构化实验记忆 | 衡量经验复用 |
| B6 | 同 B4 | 多分支树搜索 | 衡量分支探索而非搜索预算膨胀 |
| B7 | B1+B4 分层 | Agent 生成空间/代码 + HPO 内核 | 测试推荐融合架构 |

**严格性提醒**：B0–B3 在相同 HP 空间内可直接比较优化算法；B4–B7 允许更广泛的程序编辑，不能宣称所有方法处于相同动作空间。它们可在**相同总资源/评估规则**下比较“系统能力”，但论证算法优劣需另设空间控制实验。

<a id="s21-14-1"></a>

#### 21.14.1 完整实验报告最低字段

| 维度 | 必须记录 |
|---|---|
| 输入数据 | 版本 hash、训练/验证/测试分割、许可证、获取时间 |
| 研究契约 | 目标、指标、搜索范围、允许动作、禁止动作、审计人 |
| 模型与策略 | Agent 模型版本、temperature、prompt hash、HPO sampler 及参数 |
| 硬件 | GPU 型号/显存、CPU、驱动/CUDA、功耗限制、并发 |
| 依赖 | Git commit、container digest、Python/package lock、kernel 版本 |
| 每轮 | 假设、patch diff、种子、训练时间、真实总时间、cost、状态 |
| 失败 | 失败类别、修复时间、是否复发、OOM 占比、浪费预算 |
| 优化轨迹 | best-so-far 曲线 vs GPUh、美元、墙钟时间 |
| 泛化 | 独立测试、多 seed、多任务/预算/规模迁移 |
| 科学证据 | 控制实验、消融、显著性/效果大小、被证伪假设 |

<a id="s21-14-2"></a>

#### 21.14.2 避免 AutoResearch 评测中的三个典型陷阱

1. **验证集多次复用**：Agent 会自适应学习验证偏好。最好采用分级 development / audit / final test，最后的 final test 只能用于冻结后的确认。
2. **把更大的动作空间解释成“搜索算法更优”**：若一组能改优化器和模型代码，另一组只能调 HP，则比较的是整个系统能力而非采样器的同空间效率。
3. **省略失败 trial**：crash、OOM、timeout 和无效模型都是方法成本的组成部分；必须纳入成功率和真实预算。

<a id="s21-16"></a>

### 21.16 值得做成论文的十个交叉研究问题

| 编号 | 研究问题 | 可检验假设 | 对应实验/消融 |
|---|---|---|---|
| X1 | 何时调用 LLM，何时继续 BO？ | 不确定性驱动的路由比每次都调 LLM 更高效 | 固定 0%/10%/30%/50%/100% LLM 比例 vs 学习式路由 |
| X2 | Agent 能否学会“先定义更好空间再搜索”？ | 任务条件化的空间扩展提高跨任务表现 | 固定搜索空间 vs Agent 构造空间 + 同一 HPO |
| X3 | 代码 patch 的价值能否用 surrogate 预测？ | diff 特征 + 结构化 trial 史可减少昂贵无效实验 | patch embedding/AST/历史代理对比 |
| X4 | 能否把失败的条件约束跨分支共享？ | 全局约束记忆降低 OOM、重复 debug | 删除/启用 shared error memory [AR07] |
| X5 | 单一“最优分支”会损害创新吗？ | 多样性约束的树搜索发现更多非局部改进 | greedy vs best-first vs novelty tree |
| X6 | 五分钟赢的设计能否赢在长训练？ | 短预算 ranking 对长预算存在系统偏差 | 5/30/180 分钟及多模型规模 rank correlation |
| X7 | Agent 是否会对验证集 Goodhart？ | 验证查询次数与测试退化相关 | 控制查询预算、独立 holdout |
| X8 | 学习的 World Model 何时值得相信？ | 仿真预筛能省成本但会产生偏差 | 真实试验比例与 world-model 校准 [AR08] |
| X9 | 能否在等美元成本下优于 AutoML？ | 混合系统在某些任务区间具有优势 | CPU/GPU/API/失败全成本评测 |
| X10 | 自动研究能够解释而非仅拟合吗？ | 强制假设—反证实验提升可泛化成果占比 | 仅分数反馈 vs 加入假设和机制消融 |

**优先推荐课题**：**“Budget-Aware Hierarchical AutoResearch: Agentic Search-Space Expansion with Classical HPO and Protected Evaluation”**。创新落点不是将 LLM 包一层 Optuna，而是证明：在**固定总预算、相同冻结评估器、多种任务与代码候选**下，Agent 低频构造新空间/新代码，HPO 高频优化，探索记忆共享失败约束，最终在真实独立测试中比各组成部分更有效。

<a id="s21-16-1"></a>

#### 21.16.1 一个可执行的最小研究计划（建议值）

**阶段 0（可复现基线）**：挑选 4–8 个小规模 tabular 数据集和 1 个短训练语言模型任务；锁定任务说明、split、容器与预算，先确认 B0/B1 正常工作。  
**阶段 1（单 Agent）**：添加只写白名单文件的 Agent，以“结构化提案→工具执行→数值验证→回滚”的方式运行，与 B1 比较。  
**阶段 2（分层混合）**：TPE/SMAC 常态运行，Agent 每隔 N 个 trial 或在改善停滞时提出新空间/代码；控制 Agent token 预算。  
**阶段 3（科学性验证）**：对代表性收益做独立 holdout、多 seed、多训练预算、机制消融、错误修复与预算曲线分析。  
**阶段 4（论文叙事）**：严格分开**预测性能收益**、**搜索效率收益**、**算法研究价值**三个结论；无独立机制证据时只声称系统优化。

### 21.17 反常识清单：六个容易写错的结论

- **错**：“AutoML 就是传统 HPO。” **正**：HPO 是 AutoML 核心子问题之一，AutoML 包括任务端到端的更广泛自动化。
- **错**：“Agent for AutoML 一定比传统 AutoML 自主性更高，因而结果更好。” **正**：自主性、有效性和可靠性是不同维度，需公平实验检验。
- **错**：“autoresearch 开创了 ML 代码搜索。” **正**：此前已有 NAS、遗传编程、AutoML pipeline search、AIDE 等代码/结构探索工作；新在**协议的极简实现与传播方式**。
- **错**：“五分钟实验就是同等计算成本实验。” **正**：原版预算为**训练时间**；编译、CPU、LLM、初始化和失败重试的总开销不一定相同。
- **错**：“可修改整个训练源码就是无约束 AutoResearch。” **正**：原版受唯一可编辑文件、不可改 `prepare.py`、已有依赖、固定评测器与目标严格约束。
- **错**：“连续降低验证 loss 说明新发现经独立证实。” **正**：这只初步说明在当前开发评估协议下优化成功，仍要经过复现、holdout 与机制验证。
