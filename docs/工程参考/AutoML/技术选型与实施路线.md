## 16. 工程技术选型、路线图与决策树

<a id="s16-1"></a>

### 16.1 按场景的实际选型

| 场景 | 首选方案 | Agent 角色 | 不优先考虑的路线 |
|---|---|---|---|
| 中小型表格数据，强调预测质量 | AutoGluon | 任务解析、指标与质量约束确认 | 无边界的自由代码搜索 |
| 低算力 CPU、几分钟得到模型 | FLAML | 时间预算管理、错误归因 | 大量深度 NAS 试验 |
| 自定义模型/损失/复杂超参 | Optuna/SMAC | 构造搜索空间、识别条件参数 | 直接由 LLM 手工猜数值 |
| 分布式深度训练 | Ray Tune + ASHA/BOHB | 搜索策略调整、经验选择 | 每个 epoch 都调用 LLM |
| 标准化数据科学平台 | AutoML 内核 + Agent 编排层 | 数据/评测契约、workflow 工具调用 | 无评估系统的聊天式编排 |
| Kaggle/开放式工程研究 | AIDE/R&D-Agent 思想 | 代码实验与假设树搜索 | 用自动分类训练器代替开放任务 |
| 数据科学 Agent 研究 | Data Interpreter/DeepAnalyze 思路 | 多步骤数据分析、报告 | 只对模型 AUC 做单一评测 |
| AI Agent 策略训练研究 | ML-Agent 类交互 RL | 学习试验选择与反馈策略 | 只堆叠多 Agent 角色提示词 |

<a id="s16-3"></a>

### 16.3 建议分期推进：12 周研发路线

> 时间只是组织排期示例，实际由人员、数据治理和计算资源决定。每一阶段应有可验收的交付物与退出条件。

**第 1–2 周：问题定义与数据契约**  
建立数据集快照、split rules、指标、基线任务清单、安全权限模型；输出 10–20 个代表性任务与初始成本记录。完成后能在没有 LLM 的情况下复跑评测。

**第 3–4 周：AutoML Baseline 与运行基础设施**  
接入 AutoGluon/FLAML，完成任务队列、训练日志、资源限额、模型产物、环境 lock；交付 baseline 性能分布、失败率和训练成本曲线。

**第 5–6 周：最小可行 Agent Orchestrator**  
允许只读 profile、选择引擎、配置预算、解读失败；不允许修改测试集。交付成功执行率与基线对比。

**第 7–8 周：受控适应性搜索**  
引入 Optuna/Ray、有限的 feature proposal、结构化案例检索；交付相同总预算下的 A/B 比较与跨任务统计。

**第 9–10 周：长程经验与验证**  
加入实验树、错误标签、记忆检索、模型结构化评估和泄漏红队测试；做 no-memory/no-RAG/no-ensemble 消融。

**第 11–12 周：验收与论文/产品报告**  
固定评测任务和所有版本，至少 3 seeds；产出质量/成本/风险三维对比、Model Card、系统部署 SOP 和回滚方案。

<a id="s16-4"></a>

### 16.4 最小团队角色建议

- AutoML/ML 工程：管线、评估、模型诊断；
- Agent/LLM 工程：计划、工具定义、记忆与策略；
- 平台/SRE 工程：算力调度、沙箱、可观测性；
- 数据治理/产品：标签定义、访问权限、业务损失；
- 安全/合规审阅：部署权限、许可、生产上线审批。

对于早期原型，可以由少量跨领域工程师兼任，但**不要让同一个 Agent 同时拥有修改评分规则和评估自身成绩的权限**。

<a id="s16-5"></a>

### 16.5 决策树

```text
是否为标准监督学习表格任务？
├─ 是
│  ├─ 训练预算小/CPU为主 → FLAML 基线
│  └─ 质量优先/可负担集成 → AutoGluon 基线
│      ├─ 只需调参 → Optuna/SMAC
│      └─ 需要复杂数据语义与工具协作 → 加受限 Agent 层
└─ 否
   ├─ 深度网络结构搜索 → AutoDL/NAS/分布式训练工具
   ├─ 复杂多步数据分析 → Data Science Agent + 数据工具 + 审计
   └─ 开放式模型研发/代码改动 → AIDE/R&D-Agent 风格实验树
       └─ 大量任务和轨迹可用？
           ├─ 是 → 研究策略学习/经验记忆
           └─ 否 → 单 Agent + 工具，先保障可复现
```
