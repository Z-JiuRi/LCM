# LCMAgent 的 DeepMIMO 场景选型

日期：2026-10-25。状态：官方目录与部分几何核验；下文实验用途为项目建议，未训练模型、生成 CSI 或验证 LCMAgent 收益。

> 需求澄清：用户的目标是**拼接几何地图后重新计算信道**，不是直接拼接现成 CSI，也不是只展示独立小场景。该目标的全量选材入口见[场景分类与几何拼接素材清单](DeepMIMO场景分类与几何拼接素材清单.md)。本页保留此前偏向现成信道实验的选型建议与原始核验记录，不再作为几何拼接素材的完整清单。

## 推荐结论

建议最先使用 **`asu_campus_3p5`** 做 CSI 压缩反馈与跨空间区域的模型生命周期实验；随后用 **`asu_campus_3p5_dyn`** 研究移动链路下的证据时效。若先做单侧波束用例，则把 **`o1_28` + `o1b_28`** 提到前面。**`boston5g_3p5`** 用于开发完成后的外部地图测试，**`city_99_shanghai_3p5`** 是可选的第二个外部域。

这一排序依据本项目[研究问题](../../设计草案/LCMAgent架构设计草案.md)：有成本且会过期的证据、模型选择/校准/适配，以及可靠激活与恢复。地图复杂程度本身不能证明 Agent 的必要性。

| 优先级 | 场景 | 已核验的官方事实 | 建议用途 | 使用边界 |
|---|---|---|---|---|
| 1 | `asu_campus_3p5` | 3.5 GHz；目录 1 TX；静态；InSite；官网预览有 35 个建筑对象与 1 个地形对象 | 固定 BS，在分离空间块上构造训练、校准、适配、测试域；先研究 CSI 模型选择与补测预算 | 位置网格不自带时间；不可随机打散相邻点后声称跨域泛化 |
| 2 | `asu_campus_3p5_dyn` | 3.5 GHz；100 个快照目录；2 TX；已抽取第 1、51、100 个快照的原始几何与位置 | 移动 TX 造成的链路变化、证据过期、候选复测与恢复 | 抽查快照建筑与 RX 相同，变化的是一个 TX；不能叫作已验证的动态遮挡数据 |
| 3 | `o1_28` + `o1b_28` | 28 GHz；目录分别 18 / 12 TX；O1 为街道/路口；O1B 增加遮挡与反射面 | 单侧波束选择、扫描预算、传统扫描回退；遮挡变体作为压力测试 | 本次 ZIP 下载返回 HTTP 429，未独立核验包内几何；不能把两包直接视为只改变遮挡的配对实验 |
| 4 | `boston5g_3p5` | 3.5 GHz；目录 1 TX；静态；官网预览返回 67 个建筑对象与 1 个地形对象 | 与 ASU 同频段的外部城市域，用于冻结策略后的泛化评价 | ASU 与 Boston 的反射/绕射/散射配置不同；跨域差异不是纯地理效应 |
| 可选 | `city_99_shanghai_3p5` | 3.5 GHz；目录 3 TX、76,425 RX；静态；官网预览返回选中链路 1 TX | 第二个外部城市域、后续多站点实验 | 本次只展示当前链路的几何与抽样 RX；未验证三个站点的全部信道 |

优先选择 v4 条目名称，避免把旧版页面中的 BS 编号、网格计数和当前 Python API 的 set ID 混用。目录 RX 总数可能包含兼作 RX 的 TX，且不等于同时在线 UE 数；下载包可能保留更多网格点。实际批次应以包内参数、坐标及有效路径掩码为准。

## 动态 ASU 的实际核验

原始归档大小为 1,732,593,170 字节。本次使用 HTTP Range 只读取 ZIP 中央目录以及三个快照的 `objects.json`、`vertices.npz`、`params.json`、TX/RX 位置 NPZ，没有下载完整信道矩阵。ZIP 成员按未压缩长度和 CRC 校验；保留来源文件及 SHA-256 清单。

按归档文件夹名排序，抽查结果如下（原始米制、Z 轴向上）：

| 快照序号 | TX set 1 坐标 | TX set 2 坐标 |
|---|---|---|
| 1 / 100 | $(170.449,-115.169,3)$ | $(190,106,20)$ |
| 51 / 100 | $(119.449,84.831,3)$ | $(190,106,20)$ |
| 100 / 100 | $(-125.551,84.831,3)$ | $(190,106,20)$ |

三份已抽查快照的对象面片坐标一致，RX 抽样坐标一致；第一个 TX 移动。这里的序号只是文件夹排序，不把文件名中的生成时间当作物理采样时间，也没有推断中间移动路线。尚未检验其余 97 个快照。

静态 ASU 的官网预览 TX 位于 $(166,104,22)$，而动态包使用上述两个 TX。静态/动态 ASU 的对象数、追踪阶数等也不同，因此不建议直接用“静态 ASU → 动态 ASU”作为单一运动因素的因果对照。优先在动态包内部做快照间比较。

## 最小实验使用方式（待执行）

1. **CSI 主线**：先用静态 ASU、固定一个 TX、固定阵列/带宽/子载波。按连续空间块划分训练、阈值校准、候选适配和测试；保持隔离带。比较保持原模型、补测、候选切换与适配的质量—成本关系。
2. **动态扩展**：在动态 ASU 包内核对全部快照的身份映射、运动方向和采样时间；以完整轨迹/episode 分组测试。若研究移动 UE，不能把移动 TX 自动改称移动 UE；需要明确链路角色和适用假设。
3. **波束分支**：O1 内先构造有合法坐标映射、明确时序假设的通行位置序列。O1B 用于额外压力测试；对齐 TX、RX 高度、采样坐标及材料/追踪设置后才能讨论遮挡效应。3.5 GHz 对应版本 `o1_3p5` / `o1b_3p5` 可用于同频段分支，不能仅改变信道生成参数冒充另一载频。
4. **外部泛化**：冻结配置、阈值和策略后在 Boston 测试，再考虑上海。完整报告域间仿真参数变化。

所有策略使用相同候选模型、工具、证据权限、预算和执行层。至少包含无 LCM、规则/阈值、统计检测、非 LLM 主动证据选择。CSI 指标可用 NMSE / SGCS、参考测量开销和错误更新次数；波束使用增益损失/速率代理、扫描次数与恢复延迟。静态位置、动态快照、无路径/断链点都需保留明确语义。

DeepMIMO 提供传播环境及路径数据，不提供 LCMAgent 的内存/温度状态、控制消息丢失、模型配对协议或激活事务。上述执行与故障实验仍需项目另行实现；不可把射线追踪结果写成安全发布机制已验证。

## 本地 3D 展示

入口：`tools/scene-studio/deepmimo.html`，启动 Scene Studio 后访问 `/deepmimo.html`。使用现有 Three.js / TypeScript / Vite，新增一个只读页面，保持原编辑器的数据格式。

- 已展示静态 ASU、动态 ASU 三快照、Boston、上海；支持旋转/缩放/平移、俯视、RX 图层及图片导出。
- 官方几何来源分为官网预览 API 和动态包原始面片；没有用盒状建筑臆造场景，也没有新增规划轨迹、传播路径或波束结果。
- 官网预览的多边形面片去除尾部零填充；渲染时按主平面三角化。原始坐标及几何来源保留在本地文件中。颜色、球体大小、点大小和边线是显示选择，不是电磁参数。
- 静态预览按 API 索引步长抽样；动态包的 RX 按数组索引抽样。抽样不表示轨迹，也不表示独立统计样本。
- O1/O1B 的预览 API 返回目录不存在，下载接口返回 HTTP 429；本次不展示替代几何。
- 页面是几何浏览器，不是 DeepMIMO/Sionna 信道生成器；目前不支持在此页面修改原始面片并重新仿真。

可复现脚本：[抓取几何](../../../tools/scene-studio/scripts/fetch_deepmimo_geometry.py)、[转换展示数据](../../../tools/scene-studio/scripts/export_deepmimo_gallery.py)。来源哈希：[manifest.json](../../../output/deepmimo-scenes/source/manifest.json)。
