# CSI 压缩反馈：QuaDRiGa 与 DeepMIMO 数据生成方案

> 日期：2026-10-25。状态：官方资料与源码核验后的候选数据方案；未安装生成器、下载完整场景或运行无线仿真。参数、样本数和门槛是本项目 pilot 建议，不是标准要求或已验证结果。所有公式使用 `$...$` / `$$...$$`。
>
> 本次按用户指示优先准备 CSI 压缩反馈数据。现有[实验方案](../../设计草案/实验方案.md)仍包含波束主用例的旧顺序，开始确认性实验前需要另行对齐；本文不把新方案写成已完成实验。

## 1. 建议先走的路线

先用 **DeepMIMO v4 的已有射线追踪场景**生成空间分区的 CSI，建立压缩重建与跨区域测试；再用 **QuaDRiGa 的连续轨迹和场景分段**构造时变 CSI，研究何时补测、切换、适配和发布模型。两种工具分别接入统一格式，不要求相互串联，也不要求先自建射线追踪地图。

| 问题 | DeepMIMO | QuaDRiGa |
|---|---|---|
| 数据如何产生 | 已有或新计算的射线路径，经阵列/OFDM 配置生成信道 | 场景、布局、轨迹和统计参数生成多径信道 |
| 本次优先用途 | 区域差异、跨位置/站点泛化、压缩模型数据集 | 连续移动、场景过渡、证据变旧、反馈时延 |
| 动态能力 | v4 有 Doppler、显式时间轴和 DynamicDataset | 原生轨迹演化、空间一致性与分段合并 |
| 开始所需环境 | Python；已有场景无需本地重跑射线追踪 | MATLAB 或 Octave；先做 CPU 小规模运行 |
| 仍需自己实现 | 编解码器、反馈链、模型更新和生命周期环境 | 同左 |

依据：[DeepMIMO 生成教程](https://www.deepmimo.net/docs/tutorials/3_channel_generation.html)、[动态场景教程](https://www.deepmimo.net/docs/applications/5_dynamic_rt.html)、[QuaDRiGa 官方项目](https://github.com/fraunhoferhhi/QuaDRiGa)。两者均生成仿真信道，不能写成现场实测。

## 2. 先明确要生成的对象

首版采用 FDD 下行、单天线 UE、单 BS 的压缩反馈模型。统一保存复数频域真值：

$$
\mathbf H_t^{\mathrm{true}}\in\mathbb C^{N_r\times N_t\times N_f}.
$$

原始序列按 `[episode, snapshot, rx_ant, tx_ant, subcarrier]` 组织，变长轨迹可分 episode 文件。静态点集只保存 sample ID 和坐标；没有轨迹与时间依据时，不能把用户行号当时间。

数据链为：

```text
信道生成器 → 完整复数 H_true + 配置/位置/时间
          → 可选的 CSI 估计误差 → H_est
          → 固定预处理 → UE encoder → 量化/反馈 → BS decoder
          → 完整频域重建 → 当前时刻质量与反馈代价
```

第一阶段可以设完美 CSI 和无误反馈链，仅验证压缩。第二阶段再分别加入估计误差、量化、反馈延迟/丢失；每次增加一个可归因因素。简单加噪只是估计误差代理，不等于已模拟 CSI-RS、导频估计和 PUCCH/PUSCH。

## 3. 一个可开始的 pilot 配置

| 项目 | 建议起点 | 需要固定或检查的内容 |
|---|---|---|
| 载频 | $3.5\,\mathrm{GHz}$ | DeepMIMO 跟随真实场景载频；不能只改名称就改变射线追踪结果 |
| BS / UE | $32$ 阵元 ULA / $1$ 阵元 | 阵元位置、极化、朝向、排列及半波长间距 |
| 带宽 | $20\,\mathrm{MHz}$ | 这是通用 OFDM 研究网格，不声称精确匹配 NR numerology |
| 完整频域维度 | $N_f=256$，选择全部子载波 | 明确索引、频率偏移、时延参考和是否启用滤波 |
| 角–时延截断 | 先检查 $K=32$，必要时增到 $64$ 或 $128$ | 根据训练/开发集能量保留率选定，最终测试不参与选择 |
| 模型输入 | `[2, 32, K]`，实部/虚部两个通道 | FFT 方向、归一化和轴顺序属于模型契约 |
| latent 长度 | $M\in\{512,128,64\}$，先试 $128$ | 必须同时注明输入的实数维度 |
| latent 量化 | 先测不量化上界，再试 $b=8$ 或 $4$ bit | 动态范围、饱和率、尺度等边信息计入开销 |
| 首次生成规模 | 先 $2{,}000$ 个空间点检查格式，再扩展约 $10^4$ 样本 | 这是冒烟预算，不是充分训练或统计保证 |

若 $N_t=K=32$，输入为 $2N_tK=2048$ 个实数，定义本项目的维度压缩率：

$$
\gamma=\frac{M}{2N_tK}.
$$

因此 $M=128$ 对应 $\gamma=1/16$。量化后每次反馈至少包含：

$$
B_{\mathrm{feedback}}=Mb+B_{\mathrm{scale}}+B_{\mathrm{header}}+B_{\mathrm{protection}}.
$$

本项目按实数 latent 计数，不能与按复数维度定义的压缩率直接混用。权重下载和训练数据回传单独计费，不能混成零成本的模型更新。

## 4. 两类数据各怎么造

**DeepMIMO 首批数据**：使用官方 quickstart 的 `asu_campus_3p5`，固定一个 BS/接收点集；按地图划出区域 A、B、C。A 用于源域训练/开发，B 提供有限适配数据，C 或 B 中独立的空间块用于确认性测试。LOS/NLOS 状态以路径元数据为依据，不把地图区域名称当成标签。

将区域标签、坐标和用户 ID 与 CSI 一起保存。静态地图只能先回答“空间分布不同后模型是否退化”，不能证明移动过程相位连续或模型更新改变了未来网络状态。具体 API 见[DeepMIMO 指南](../../工程参考/CSI数据生成/DeepMIMO生成指南.md)。

**QuaDRiGa 时序数据**：固定同一套天线和 OFDM 约定，先分别生成 UMi LOS 与 UMi NLOS 的多条轨迹；随后在单一 layout/连续 track 内设置场景分段，由生成器处理过渡。保留实际速度、位置、距离和快照时间，避免逐快照重新设随机种子。具体 API 见[QuaDRiGa 指南](../../工程参考/CSI数据生成/QuaDRiGa生成指南.md)。

两工具输出不能直接拼成“真实连续运动”：模型体系、散射几何、功率尺度及相位参考不同。先分别训练/评估，再将跨生成器测试作为单独的压力实验。

## 5. 最重要的预处理检查

对于单天线 UE，把频域矩阵按天线和频率排列。本文统一使用前向单位化 DFT 矩阵：

$$
\mathbf H_{\mathrm{ad}}=\mathbf F_{N_t}\mathbf H_{\mathrm f}\mathbf F_{N_f}^{H}.
$$

这只是本项目明确的变换约定；与其他代码比较时必须对齐轴和正负号。截断到前 $K$ 个时延 tap 前，计算：

$$
\eta_K=\frac{\|\mathbf H_{\mathrm{ad}}[:,0:K]\|_F^2}{\|\mathbf H_{\mathrm{ad}}\|_F^2}.
$$

如果 $\eta_K=0.95$，即便保留部分完全恢复、其余补零，完整信道 NMSE 的理论下限也是 $10\log_{10}(0.05)\approx-13.01\,\mathrm{dB}$。这是数学算例，不是工具实验结果。不能把截断误差归为 encoder/decoder 退化。

在 $20\,\mathrm{MHz}$ 网格下，时延分辨率约为 $50\,\mathrm{ns}$，$32$ 个 tap 覆盖约 $1.6\,\mu\mathrm{s}$；绝对传播时延可能让能量落到这个窗口外。若要做同步对齐，必须固定可实现的时延参考并记录规则，不能每帧利用隐藏真值任意平移。

归一化只在训练集拟合并冻结；保留原始幅度。若按样本归一化，恢复尺度的来源及反馈位数必须明确。不要把每域独立 min–max 归一化当成免费适配。

## 6. 数据划分与模型更新时序

| 数据角色 | 用途 | 约束 |
|---|---|---|
| source train / validation | 训练和选择初始压缩模型 | 按区域、轨迹或 realization 分组 |
| monitor stream | 检查模型是否退化、是否请求额外证据 | Agent 不直接获得仿真器的全量真值 |
| adaptation train / validation | 更新候选模型、选择超参数 | 只使用决策时刻之前已取得且已计成本的数据 |
| future test | 比较更新后候选与旧模型 | 不进入 AutoML 搜索或提示词 |

同一位置或信道的不同噪声副本、相邻时刻、共享散射 realization 的轨迹必须归入同一组。空间隔离距离应由相关性检查决定；时间窗口间留 gap，但 gap 本身不能证明独立。

生命周期 episode 建议覆盖：稳定区间、真实持续漂移、短暂扰动、返回旧场景，以及更新耗时超过有效窗口的情况。形成以下候选动作：继续使用、补测、切换已有配对、校准/微调、重新搜索、等待或回退。

环境变化由轨迹或场景驱动，模型更新改变重建质量和业务控制结果，不应反过来修改物理信道真值。双侧压缩模型的更新要保存 encoder/decoder digest 和共同激活时刻，配对错误作为独立故障注入。

训练所需 CSI 如何到达网络侧也要建模：全量上传、UE 本地训练或其他采集方式有不同成本。不能让 AutoML 免费读取未来 CSI 或全部 UE 真值。

## 7. 必须保存与报告什么

至少保存 `generator/version/commit`、场景及文件校验和、随机种子、BS/UE/轨迹 ID、时间/位置、阵列坐标、载频、频率网格、延迟参考、完整 `H_true`、可见 `H_est`、预处理版本、split 组以及失效/缺失掩码。隐藏真值单独存放，供评价器访问。

模型侧报告裁剪域 NMSE 与完整频域 NMSE；后者需逆变换并恢复幅度：

$$
\mathrm{NMSE}_{\mathrm{dB}}=10\log_{10}\left(\frac1N\sum_{i=1}^{N}\frac{\|\widehat{\mathbf H}_i-\mathbf H_i\|_F^2}{\|\mathbf H_i\|_F^2}\right).
$$

明确这是“先平均逐样本比值，再取对数”，不是平均 dB。另报相关性、量化位数、训练和权重传输成本、退化持续时间及误更新次数。只有接入预编码/链路模型后才报告对应吞吐或 BLER 收益。

推荐基线为固定模型、周期更新、阈值/序贯检测后更新、非 LLM 主动证据策略，以及同工具预算下的 LCMAgent；PCA/线性压缩配合相同量化预算可做模型侧对照。简单 DFT/PCA 基线不能冒称完整 3GPP Type II 实现。

## 8. 实施顺序与阅读入口

1. 先生成约 $2{,}000$ 个 DeepMIMO 样本，验证非零/有限值、坐标、形状、频率网格和 FFT 往返。
2. 测量截断能量，冻结预处理；按空间组训练一个 CsiNet 风格模型，建立重建误差与 bit 开销基准。
3. 用独立区域做有限适配与未来测试，先确认“更新有收益、也有成本”确实成立。
4. 加入 QuaDRiGa 连续轨迹和延迟，用相同候选/预算比较何时更新。
5. 最后增加双端配对故障、反馈失效和可选链路业务指标。
