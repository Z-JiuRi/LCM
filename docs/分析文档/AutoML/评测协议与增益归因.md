## 15. 实验设计、消融与可复现研究计划

<a id="s15-1"></a>

### 15.1 目标：严格证明 Agent 层本身的贡献

推荐研究假设：

- **H1**：在同等总成本下，Agent 可以缩短首次达到可接受性能的时间。
- **H2**：Agent 结合元经验，可在任务分布变化时优于固定搜索空间和固定 budget strategy。
- **H3**：代码树搜索在需要特殊特征工程的任务上有显著贡献，但标准表格任务上不一定稳定优于强集成 AutoML。
- **H4**：结构化经验记忆能够减少重复失败和无效试验。
- **H5**：确定性评估护栏与审批机制可降低泄漏与非法工具调用，而没有不可接受的性能损失。
- **H6**：在相同搜索能力条件下，经 ML 任务轨迹训练的轻量 agent 具有更佳推理成本—任务成功率权衡。

<a id="s15-2"></a>

### 15.2 基线矩阵（至少这些）

| 组 | 方法 | 变量控制目的 |
|---|---|---|
| B0 | Dummy/linear/tree 基线 | 数据与标签流程是否成立 |
| B1 | AutoGluon 固定 preset + 固定时限 | 高质量成熟 AutoML 对照 |
| B2 | FLAML 固定时间预算 | 成本敏感 AutoML 对照 |
| B3 | Optuna/SMAC 相同模型族 + 相同评测 | 搜索器能力对照 |
| A0 | LLM 一次性生成代码，不允许执行迭代 | 纯语言模型作用 |
| A1 | LLM + tool calling + 单链反馈 | 普通 Agent 工作流 |
| A2 | LLM + 检索历史经验 | 案例迁移增益 |
| A3 | LLM + 代码树搜索 | 多分支探索贡献 |
| A4 | LLM + AutoML kernel + evaluator | 混合架构真实收益 |
| A5 | A4 + 选择性记忆/多 agent | 记忆及协作的边际贡献 |

每个 Agent 组都应以相同模型版本、token 上限、计算预算、数据访问权做比较；不能给 A4 两倍 GPU 却声称规划更智能。

<a id="s15-3"></a>

### 15.3 任务集设计

**第一级：标准表格任务**。选 AMLB/OpenML 中具有不同数据规模、类别平衡、缺失/稀疏程度的任务，固定 train/val/test。  
**第二级：复杂真实数据**。引入按时间分割、分组结构、类别漂移、跨表连接和异常列；记录数据治理强约束。  
**第三级：开放式机器学习工程**。选择 MLE-bench Lite 中可复现任务。  
**第四级：数据科学与研究任务**。在 DSBench、MLGym 或 MLRC-Bench 上评价规划与分析能力。

任务选择应预先注册，不能只展示 Agent 最成功的 3 个数据集。

<a id="s15-4"></a>

### 15.4 消融方案

| 消融 | 保留内容 | 移除内容 | 预期说明 |
|---|---|---|---|
| no-RAG | agent+AutoML | 历史案例检索 | 经验迁移是否必要 |
| no-reflection | 任务规划和执行 | 失败归因与总结 | 分步反馈的边际收益 |
| no-tree-search | 顺序试验 | 并行候选分支 | 搜索树是否抵偿成本 |
| no-ensemble | 搜索器和候选 | 集成 | 收益来自搜索还是模型组合 |
| no-autoML-kernel | agent自由代码 | 标准 AutoML 执行器 | AutoML 内核的作用 |
| no-memory | 全部其他功能 | 跨任务记忆 | 是否真的学会迁移 |
| no-guardrails | **仅在模拟/隔离红队任务中**移除 | 执行及评估约束 | 风险量化，严禁生产实验 |
| learned-policy vs prompt | 相同工具/算力 | 只替换 agent 决策策略 | 策略学习是否值得训练成本 |

<a id="s15-5"></a>

### 15.5 统计推断与报告格式

1. 每个任务执行 $\ge 3$ 种独立随机种子，预算允许时用 $\ge 5$；
2. 主指标用任务级成对差分，绘制 bootstrap 置信区间；
3. 多任务评价使用平均排名、win/tie/loss、失败率与成本曲线；
4. 尽量报告推理分数均值与方差，避免只汇总“最好的一次”；
5. 公布 environment digest、完整 prompt 模板、task ID、trial log 和代码快照；
6. 将资源预算与 LLM API 成本的换算规则附录公开。

统计显著不等于业务显著。AUC 从 0.851 提升到 0.852，若增加十倍 GPU 成本和两倍上线延时，可能并不值得部署。

<a id="s15-6"></a>

### 15.6 三项高价值 benchmark 扩展课题

**课题 A：带真实泄漏陷阱的 Agentic AutoML benchmark**。系统构造隐藏后验字段、按实体跨时间泄漏、目标编码错误等任务，考察 Agent 是否能在性能诱惑面前阻断作弊方案。指标为预测效果、泄漏识别准确率与违规执行次数。

**课题 B：跨数据集 memory transfer benchmark**。历史任务被随机/领域分割，研究跨行业、新领域、新类别比例条件下的记忆正迁移/负迁移；衡量取得同等分数所需的试验次数和成本。

**课题 C：预算自适应 Agent benchmark**。给定不均匀 GPU 成本、API 计费与队列拥堵，测试 Agent 是否能动态切换 FLAML/AutoGluon/Optuna/基础模型与停机策略。

这些属于本报告建议的研究设计，并非已经发表的 benchmark 名称。

<a id="s20-3"></a>

### 20.3 实践中最容易遗漏的十个检查点

1. 算法搜索空间合理，但标签定义可能从一开始就错了。
2. 使用固定随机种子不代表 GPU 并行、底层库完全确定。
3. 更高的交叉验证分数不代表真实线上提升。
4. 训练测试分离不充分时，Agent 搜得越久可能错得越厉害。
5. 任务切分不匹配真实部署时间会导致严重的未来信息泄漏。
6. 只有成功 trial 的平均性能会高估复杂 Agent 系统收益。
7. 硬件不一致时，时间预算和成本不可直接比较。
8. 大量记忆不等于有效经验；没有质量过滤会造成负迁移。
9. 开源源码许可与模型权重、数据许可可能不同，需要分别检查。
10. 任何“已完成部署/已通过测试”的自然语言陈述都必须回到工具返回的可信状态确认。

## 4. 反证：agent 的增益到底从哪来

这一节是本次调研最重要的部分，因为它直接决定"agent 必要性"该如何被证明。

**反证 1 — 增益可能只是热启动的默认配置**（`2606.21641`）。在 8 个 PMLB 表格基准、40 个 (task, seed) 单元、预算匹配 + 配对检验 + bootstrap CI 的协议下：LLM advisor 的强首点并非 LLM 输出，而是循环开始前就被评估的固定默认配置，单这一项达到 88.7% mean best-CV，且 7 个 advisor 模型之间相差 $\le 0.01\,\mathrm{pp}$；LLM 自身提议只增加 +0.40pp 交叉验证精度，对 held-out test 为 −0.01pp（$p = 0.92$）；把这个默认种子也交给经典搜索后，表面优势消失。
→ **可操作推论**：任何"agent 优于基线"的主张，必须包含**去掉先验/默认策略**的消融，否则无法区分"推理有效"与"先验有效"。

**反证 2 — 经典优化器在固定预算下仍胜**（`2603.24647`）。在 autoresearch 上用小语言模型调参，固定搜索空间时 CMA-ES/TPE 一致优于 LLM agent；其中"避免 OOM"这类**可行性约束**比"搜索多样性"更决定结果；允许 LLM 直接改源码可缩小差距但不消除。最佳结果来自 **Centaur**——把 CMA-ES 的均值向量、步长、协方差矩阵这类**可解释内部状态**共享给 LLM。
→ **可操作推论**：正确的结合方式不是"让 agent 取代优化器"，而是"把优化器的显式状态暴露给 agent，让它做结构决策"。

**反证 3 — harness 可能是冗余层**（`2609.40303`）。同等时间预算、同一前沿 backbone 下，开源 SOTA harness 相对"最小 harness + read/write/bash 的单次 coding agent"无优势；分层消融指向 backbone 是主要驱动。该文明确针对"多 agent 编排器 + 专用检索子 agent"的膨胀趋势。
→ **可操作推论**：多平面/多 agent 架构不能默认自带增益，必须有 minimal-harness 基线。

**反证 4 — 短预算对比可被协议缺陷完全制造**（`2608.07303`）。Orcetra 在 513 个 OpenML 数据集上"以 57.1% 胜率击败 FLAML/AutoGluon"，但成因是：(a) 搜索结果在**测试集**上选型并上报最优（headline 指标变成数十个噪声估计的最大值），基线则用训练集选型、只碰一次测试集；(b) 预算**只在启动前检查、执行中不强制**，中位实耗 120s vs 名义 60s，是 AutoGluon 墙钟的 2.24×。改为验证集选型 + 外部强制 deadline + 等算力份额后，胜率 59.4%→34.3%，与两个对手的成对差异都不再显著；其中选型规则贡献 4.8pp。
→ **可操作推论**：预算必须是**执行器强制**的不变量，而不是规划器的自觉；选型/上报路径必须与基线同构。

**反证 5 — 结果级指标掩盖方法学失败**（`2610.14115`、`2610.04927`、`2601.16344`）。220 个任务上系统统计失效模式，指出仅看下游精度会掩盖数据泄漏与不当验证；DSGym 进一步指出**现有基准中相当比例的任务不读数据也能做对**；MLE-InsightBench 指出"注入相关任务洞见"缺乏来源控制，本身构成泄漏威胁。
→ **可操作推论**：评估对象必须包含"决策是否有效"与"证据是否合法获取"，而不只是最终分数。

**把这些放在一起看**：当前证据支持的判断是——**LLM 的价值在结构层与语义层（L3/L4），不在数值搜索层（L2）**；而"agent 架构"的价值在同等 backbone 与同等预算下尚未被证明。
