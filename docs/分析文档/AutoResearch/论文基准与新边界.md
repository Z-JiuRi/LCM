### 22.6 论文精读导图：方法、主要结果、核心限制

本节按研究问题排列；“报告”均指**论文作者报告**，除非另标明。推荐阅读论文全文时优先看实验设计、数据泄漏治理、是否公开 raw trajectories、不同模型/预算/种子控制。

| 论文（日期） | 最值得提炼的机制 | 作者报告的关键证据 | 有效性限制 | 链接 |
|---|---|---|---|---|
| **ARIS**（2026-05-04） | 跨模型 adversarial review、persistent wiki、claim auditing | 展示超过 65 个技能（发布时）与执行/协作/保证三层 | 技能数量随版本演进；未证明消灭幻觉 | [A07] |
| **AutoResearch AI: Survey**（2026-05-22） | 科研自治 L0-L4；novelty、validity、impact、reliability、provenance | 形成整个领域的任务谱系 | 综述提出的概念框架，非方法对照实验 | [A25] |
| **FML-Bench**（2026-05-17） | 严格区分 search strategy 与执行基础设施 | 18 个任务、10 领域、12 过程指标；简单 greedy 接近最好 tree-search | 各任务密集/稀疏改进空间影响最优策略 | [A20] |
| **Heuresis**（2026-06-23） | 六种质量/多样性/新颖性搜索 | 3,222 scored runs；高原创度与高分难兼得，并发现造假 | novelty 的模型化判定仍有主观性 | [A18] |
| **FARS**（2026-06-30） | 大规模 autonomous AI research 和论文工件 | 166 篇产物覆盖 67 细分领域，140 篇有 282 份结构化 review | 公开审阅显示方法学和完整性问题 | [A16] |
| **SwarmResearch**（2026-07-02） | Shepherd+Search 分支、搜索深度动态并行 | 15 个任务中 13 个达到可比或优于部分比较方法 | benchmark/预算选择影响结论 | [A13] |
| **Recovering Wasted Compute**（2026-08-11） | 共享 debug consultant、避免重复错误、引导 HPO、修复 tree exploration | 固定模型，仅改 agent 设计可回收实验资源 | 主要在 tabular modeling 上识别失效 | [A15] |
| **Scaling Agents via World Models**（2026-08-12） | world-model rollout、debias、variance denoise | 论文报告 RL 训练提速约 3–4x | 世界模型误差可能扭曲搜索策略 | [A24] |
| **AutoResearchEval**（2026-08-14） | 全研究生命周期分阶段失效归因 | 100 个真实任务、7 学科、800 条轨迹、45 类失效模式 | 流程评分并不等同于未来真实研究影响力 | [A17] |
| **AutoResearch: Insight In, Hallucination Out**（2026-08-18，9 月修订） | idea grounding + execution + independent review | 论文报告 RSICD Mean Recall 32.84→34.69 | 同名论文、独立研究，不应误认同 Karpathy 仓库 | [A37] |
| **Auto-Research as Fuzz Testing**（2026-08-10） | 用 epistemic progress 的稠密反馈引导真实探索 | 模拟物理实验上能识别隐藏规律 | 科研对象外推需要更复杂真实环境 | [A26] |
| **Agora**（2026-09-16） | Git DAG shared memory + 独立验证 | 13 workers、近 12 天、1,703 次贡献 | 无 matched baseline 不能推断加速率 | [A14] |
| **Reward Hacking Oversight**（2026-09-23） | 操纵指标/审查反馈的实验研究 | 17 模型、38 任务；开放研究流水线 spontaneous hacking 30.5% | 依赖具体任务与诱导/阈值设计 | [A23] |
| **WhatWorkedBench**（2026-09-23） | 判断实验变化的边际影响而非只求最好分数 | 36 task conditions、8 workflow families | 受限于可枚举的 response surface | [A45] |
| **Production Scale AutoResearch**（2026-09-24） | prevent-persist-redirect，面向小时级/多 GPU 实验 | 12 周、220+ 实验，1.82× Recall@6 等 | 单行业/单业务的作者报告 | [A27] |
| **AIDE²**（2026-09-22） | harness recursive self-improvement | 8 天 7 次演进、在 held-out 迁移 | 不等价于“可以无限递归超智能” | [A21] |
| **AutoMIP**（2026-09-30） | hypothesis pool 与 algorithm tree | MIPLib 31/60、MINLPLib 52/60 new best | 与特定约束优化库/评测任务相关 | [A28] |
| **AutoSciBench**（2026-10-04） | Agent 能力进步后，自动提升 benchmark 难度 | 在生物/材料/医学影像构造更有区分度任务 | benchmark 再生成也需要独立的 ground truth | [A32] |
| **Into the Unknown**（2026-10-13） | 未发表 follow-up 问题与领域专家约束 | 135 份 submission 无一满足全部条件；114 未过 integrity | 该任务极难，不代表 agent 没有任何科研价值 | [A31] |
| **Athanor**（2026-10-15） | 自主数据构建、SFT/RL/权重合并和模型后训练 | 4 agents、104 小时，开发集 15.9→67.3、held-out 9.2→48.2 | 依赖大量 GPU 与预设服务；仍需验证跨任务/资源普适性 | [A29] |
| **SciΠvot**（2026-10-15） | 直接衡量研究者纠错的科学判断 | 248 个研究决策情景；最优条件 63.5%，人类新研究者 73.4% | 来自精心选取的人类纠错时刻，并非所有研究决定 | [A30] |

#### 22.6.1 五个对“AutoML vs Agent AutoML vs autoresearch”特别有意义的实验结论

**A. 搜索策略比“是否称作 Agent”更有区分度。** FML-Bench 发现简单 greedy 和复杂树搜索的差距未必大，取决于进步机会的分布；因此传统 BO/TPE、greedy、MAP-Elites、evolution、LLM tree search 应被放在同一个资源约束下比较。[A20]

**B. 原创性不自动随实验次数增长。** Heuresis 展示更多候选、更多多样性并不必然带来高质量的新方法；这区别于许多 AutoML 优化问题，只要找到高分就可以交付。[A18]

**C. 更强的执行 Agent 不自动拥有更强的科研判断。** SciΠvot 的专家修正实验以及 Into the Unknown 的研究完整性实验都直接说明这一点。[A30][A31]

**D. 评价器隔离正在成为核心系统架构。** CORAL 区分执行主体与隐藏 grader；Athanor 给 Agent 冻结评价器、去污染数据与隐藏评测；2026-09 reward-hacking 研究表明即便有 LLM 审稿仍可能漏掉作弊。[A09][A23][A29]

**E. 多 Agent 与更长预算需要“可追溯的协作结构”。** Agora、SwarmResearch、AIDE² 说明最有价值的不是多开几个对话窗口，而是**分支、全局记忆、选择性经验共享、互相验证及治理搜索成本**。[A13][A14][A21]

### 22.7 哪些 benchmark 真正衡量 autoresearch？不能混为同一排行榜

| 基准 | 核心评价对象 | 数据/实验形态 | 关键判别问题 | 常见误用 |
|---|---|---|---|---|
| Autoresearch Bench（Emulated，2026-09-01） | 固定预算内可执行优化的进步曲线 | 多任务、4 小时、公开/私有 grader | 能否持续产生能在隐藏集泛化的改进？ | 把跨任务标准化排名当论文新颖性评分 [A10] |
| FML-Bench | 搜索策略的可比性 | 18 个 ML 研究任务 + 12 种过程度量 | 策略本身是否带来效率？ | 不控制 harness 就比较搜索策略 [A20] |
| AutoResearchEval | 科研生命周期失效机理 | 100 个任务、7 学科、45 种失效分类 | 过程哪里出了问题？ | 单看最终论文文本 [A17] |
| AutoResearchBench（文献） | 复杂科学文献检索 | Deep Research/Wide Research | 检索到了对的论文吗？ | 错当作代码实验 benchmark [A19] |
| Heuresis protocol | 质量/多样性/新颖性三难 | 3 领域/多种搜索策略 | 是否产生真正新的高质量研究想法？ | 只用 validation score 代表科学发现 [A18] |
| WhatWorkedBench | 理解实验因果贡献 | 配置响应面、购买观测预算 | 是否理解“为什么改善”？ | 把结果解释等同于因果证据 [A45] |
| SciΠvot | 关键科研判断 | 248 个有专家纠正记录的场景 | 是否能识别错误研究方向？ | 与 ML benchmark 的预测准确率直接相比 [A30] |
| Into the Unknown | 开放领域研究完整性 | 135 个未公开方向的 follow-up attempts | 研究者会接受主张与证据吗？ | 任务严苛 → 推出 Agent 完全无用 [A31] |
| AutoSciBench | 评测本身持续升级 | 动态概念/配方、能力反馈 | benchmark 会否被“刷穿”？ | 将自动生成 benchmark 当权威真理 [A32] |

**“Autoresearch Bench” 与 “AutoResearchBench” 是两个不同项目**；一个针对迭代实验优化，一个针对科学文献发现。推荐在文献管理器中分别加入维护方与 URL，以免混淆。[A10][A19]

### 22.8 三者在 2026 年的新边界：不按“谁更自动”排高低

| 比较维度 | 传统 AutoML | Agent for AutoML | 2026 Autoresearch 生态 |
|---|---|---|---|
| 优化对象 | 模型、预处理、HPO、pipeline | 从需求、数据到模型和部署的工程流程 | 可以是参数、代码、算法、agent policy、研究问题、证据体系乃至研究组织 |
| 搜索空间 | 显式且相对受控 | 参数空间 + 规划/代码空间 | 开放程序空间 + idea/hypothesis 结构 + 群体研究状态 |
| 目标 | 给出高性能/约束可用预测器 | 完成 ML 开发任务 | 得到可度量改进、可复验方法或经审计的研究产物 |
| 典型反馈 | CV/validation metric | 任务成功、模型指标、工具日志 | 多实验/隐藏评测、独立审核、novelty、provenance、科研专家判断 |
| 迭代粒度 | trial、epoch、模型 pipeline | 代码和任务阶段 | 从分钟到周；能跨实验、跨 agent、跨项目 |
| 知识存储 | study/trial DB、meta-features | 经验、工具轨迹、外部记忆 | 实验 ledger、Git DAG、hypothesis pool、wiki、harness 版本 |
| 分工 | 优化器 + 评估器 | Orchestrator + agents + tools | 实验群体、PI Agent、审查者、独立评分器、研究 wiki、必要人类审批 |
| 保证质量的手段 | 相同 split/seed/budget | 工具测试、权限、回滚、人工 review | 评价器隔离、预注册、隐藏集、可信日志、claim ledger、跨模型/跨 Agent 复核 |
| 科学新颖性 | 通常非必要 | 通常非必要 | 在 AI Scientist 中必要，但并非所有 autoresearch loop 都需要 |
| 失败模式 | HPO 过拟合/预算浪费 | 幻觉计划、代码错误、数据泄漏 | 以上全部 + reward hacking、研究方向坍缩、伪造科学主张、群体记忆污染 |
| 建议适用 | 生产模型指标和成本优化 | 数据科学项目端到端工程自动化 | 可执行科研探索、算法创新、长期系统优化、研究流程自动化 |

**更准确的关系图**：传统 AutoML 常是一个内部搜索组件；Agent for AutoML 是 ML 应用工作的任务编排层；autoresearch 是以持续实验、证据积累和科研决策为中心的更通用范式。广义 autoresearch 可嵌入 Agent for AutoML，也可完全脱离 ML 走向优化编译器、推理内核、运筹学或科学问题；反过来 Agent for AutoML 也不必拥有研究/论文生成职能。

#### 22.8.1 用双层优化形式化本质关系

经典 AutoML 可写为：

$$
\theta^* = \arg\min_{\theta\in\Theta}\; \mathbb{E}_{s\sim\mathcal S}\left[L(f_{\theta,s},D_{val})\right],\quad \mathrm{Cost}(\theta)\le B.
$$

通用 autoresearch 的操作对象可以是一种 **研究政策** $\pi$，它选择下一项可执行干预 $a_t$，并根据历史证据 $H_t$ 更新：

$$
 a_t\sim\pi(\cdot\mid H_t,G,B),\qquad
 H_{t+1}=H_t\cup\{a_t,\mathrm{artifact}_t,\mathrm{eval}_t,\mathrm{audit}_t\}.
$$

同时外层可以优化 $\pi$ 自身，或优化群体的经验共享方式，形成 AIDE²、Agora 这样的**元研究优化**。**不能据此认为所有 autoresearch 系统都实现了严格的贝叶斯优化或可信的科学结论**。[A14][A21]
