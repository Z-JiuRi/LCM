### 21.8 与 AIDE、AutoML-Agent、AI Scientist 的具体关系

不要把新项目误当作“整个研究方向的起点”。时间线与问题边界如下：

| 系统/工作 | 时间 | 关注任务 | 与 autoresearch 的重合 | 重要差别 |
|---|---|---|---|---|
| Auto-WEKA / auto-sklearn | 2013 / 2015 | CASH、元学习、集成 | 自动选择更好 ML 方案 | 主要用结构化配置和算法优化 |
| The AI Scientist | 2024 | 研究构思、实验、成文与评审 | 自动科学实验循环 | 目标更广，包含报告/论文生成和模拟审查；生成论文不等于确证科学发现 [AR13] |
| AIDE | 2025 | 代码空间树搜索、ML 工程探索 | 修改代码、执行、根据得分改进 | 明确树结构、重用分支，面向多 ML 任务 [AR05] |
| AutoML-Agent | ICML 2025 | 从数据检索到部署的完整 AutoML 流程 | 用 Agent 执行/验证 ML 实验 | 多 Agent 分工与端到端交付优先，不限于训练脚本 [AR06] |
| **karpathy/autoresearch** | 2026-03 | 单 GPU 小语言模型训练方案迭代 | 自动编程—训练—测量—筛选 | 极简受控任务、五分钟固定预算、单主分支 [AR01][AR02] |
| Centaur / autoresearch-automl | 2026-03 至 04 | 经典 HPO 与 LLM 代码/配置搜索的直接对比 | 共享相同短训平台 | 形式化比较与混合优化 [AR03][AR04] |
| Recovering Wasted Compute | 2026-08 | 自动研究 Agent 的试验算力浪费 | 失败修复、搜索轨迹优化 | 用全局 debug 经验和控制改造改善树搜索 [AR07] |
| Scaling via World Models | 2026-08 | 训练自动研究 Agent 的交互成本 | 以真实运行结果训练/反馈 | 用世界模型替代部分昂贵真实执行 [AR08] |
| Auto-RecSys | 2026-09 | 工业推荐模型长周期自动研究 | 假设→训练→迭代 | 并行跨服务器、中央记忆、技能/脚本分离 [AR10] |
| SAGE-Loop | 2026-09 | 具有失败修复和自适应集成的 LLM AutoML | 生成→验证→修复闭环 | 关注多个监督/无监督数据集与管道稳健性 [AR11] |

因此，若研究目标是**多数据集、自然语言到模型的工程交付**，AutoML-Agent 类路线更直接；若目标是**给定代码仓库下的持续算法/训练研究探索**，autoresearch 更有启发；若要验证**是否真的能进行开放式研究**，还须借鉴 AIDE 的多分支搜索及 AI Scientist/科研复现类工作对假设与证据的要求。

### 21.9 AutoResearch 大类 2026 年的前沿：不是只把循环跑得更久

<a id="s21-9-1"></a>

#### 21.9.1 Recovering Wasted Compute in Autoresearch Agents（2026-08）

作者分析将 Agent 用于表格任务时反复出现的失败：**不同分支重复修同一错误、预算充足却不做适当 HPO、名义树搜索实际上探索不足、已经做出的数据分析没有转化为后续建模决策**。论文探索将已发现的运行约束跨分支共享的全局 debug 顾问、提示和控制改造、改进搜索树策略，并报告在**不改变底层语言模型**的情况下可以改善表现。[AR07]

**对三者融合的启示**：传统 AutoML 的“所有 trial 共享失败数据/采样约束”对 Agent 研究树同样必要；不要让多个 Agent 分支重复踩 OOM、路径配置、列名不一致等已知坑。统一维护 `invalid_region_memory` / `environment_constraints` / `known_failed_patches` 能省去浪费。

<a id="s21-9-2"></a>

#### 21.9.2 Scaling Automatic Research Agents via World Models（2026-08）

这篇工作针对训练自主研究 Agent 时的**环境执行成本**：LLM 生成轨迹可批量并行，真实代码运行却占用独立 sandbox 与机器时间。论文提出 World Model RL（WMRL），以学习的世界模型替代部分真实执行，并通过在线去偏/降噪应对模拟奖励不准；作者报告在其任务条件下训练可加速约 3–4 倍。[AR08]

**重要边界**：世界模型预测是训练加速/候选排序工具，**不是最终科学证据**。Agent 若只向容易获得高模拟奖励的方向优化，将产生 world-model exploitation；任何需要发表或部署的改进仍须在真实、受保护的评测环境验证。

<a id="s21-9-3"></a>

#### 21.9.3 AutoResearch as Fuzz Testing（2026-08）

论文 **The Greatness of Science Cannot Be Planned: Agentic Auto-Research is Fuzz Testing** 提出一种值得讨论的观点：只对每次完整试验最后的单个 benchmark 分数计奖，会丢失“探索是否扩展了知识边界”的中间信号。作者借鉴灰盒模糊测试（fuzzing）的 coverage-guided 思想，倡议设计廉价、稠密的认识进展信号来指导试验，并强调最终主张仍要依赖**未被自适应复用污染的受保护验证**。这主要是**研究方法论与可检验假设**，不能被当作已普适证明的算法收益。[AR09]

**启示**：AutoML 可以只关心 final `best_score`；研究 Agent 还应关心“哪些机制被证伪了”“哪些假设覆盖不足”“新发现是否可解释、可泛化”。但新的探索分数也可能被 Goodhart 化，需要真正独立的验收标准。

<a id="s21-9-4"></a>

#### 21.9.4 Auto-RecSys：当五分钟实验变成多天任务（2026-09）

在工业规模推荐系统中，训练可能持续数天，串行 `edit→run→evaluate` 的原版循环不足以支撑研究吞吐。Auto-RecSys 提出跨服务器的**分布式异步执行**、中央持续记忆、将自然语言技能和确定性脚本分开的运行方式，以及分别演化**运行流程经验**和**研究创意**的双循环；作者报告了实验周期人工时间和执行可靠性上的改善。[AR10]

**启示**：走向工业场景时，AutoResearch 必须补齐 AutoML/MLOps 长期发展出的调度、恢复、记录、权限与版本控制能力。五分钟单分支是高质量教学基线，不是工业规模标准架构。

<a id="s21-9-5"></a>

#### 21.9.5 SAGE-Loop：闭环纠错与集成为何仍属于 AutoML（2026-09）

SAGE-Loop 强调模型生成与验证之后的多轮 trial-and-repair，并引入基于证据的自适应集成。作者在 20 个公开数据集的分类、回归和聚类任务上报告了性能、稳定性和从执行失败恢复方面的收益。[AR11] 它证明了一个术语边界：**即使没有以“AutoResearch”为项目名，AutoML 系统也可以采用与 autoresearch 高度相似的反馈闭环**；技术架构不能只凭品牌词辨认。

<a id="s21-10"></a>

### 21.10 为什么“能不断提高同一验证分数”并不等于“能做研究”？

**研究标准比优化指标更严格。** 一个模型在固定 validation 上进步，至少有以下互不等价的解释：

1. 发现了对当前数据/硬件/训练时长有效的参数组合。
2. 发现了实现层面的速度改进，使五分钟内训练更多 token。
3. 发现了模型/优化器机制上的真实改进，能够跨规模泛化。
4. 验证泄漏、随机波动、数据/代码污染或评测器缺陷造成了虚假收益。

前两项足以成为**系统优化成果**，但不能自动升格为第三项。为了判断候选方案属于哪一类，应采用逐层证据：

```text
L0  代码成功执行，目标指标得到改善
 L1  同环境不同种子/重复运行，改善仍存在
  L2  独立 holdout、不同数据或任务切分仍有效
   L3  训练时间预算与模型规模发生改变仍有效
    L4  机制消融说明“为何有效”，优于合理替代解释
     L5  独立团队复现 + 定义清楚的适用边界
```

这是一套**本文建议的证据分层**，不是原版项目自称使用的研究等级。

<a id="s21-10-1"></a>

#### 21.10.1 研究智能体需要比 AutoML 更多的结果类型

- `optimization_artifact`：最优模型或实现、固定指标、成本；
- `experiment_ledger`：所有尝试，包含失败实验、假设、patch、运行环境；
- `causal_claim`：某项机制改善结果的可检验陈述；
- `robustness_package`：多 seed、多预算、多规模、多任务结果；
- `negative_result`：失败原因与证伪范围；
- `independent_verification`：不可由 Agent 自主篡改的保留测试和复现流程。

CORE-Bench 之类研究复现基准说明，仅仅重现已知成果也是独立困难的任务；2026 年修订的 CORE-Bench 包含基于 90 篇论文的 270 项任务，用以测量自动复现能力。[AR15] 这与单次 benchmark 优化成功是两种不同能力。

<a id="s21-15"></a>

### 21.15 自动研究是否已经接近人类科研？两个反例提醒

**反例一：受控 HPO 不需要炫技**。Ferreira 等人的对照显示，在当前实验的固定 HP 空间里，TPE 等成熟方法可以比许多 LLM-only 方法更高效；让模型自己“记住最近试了多少次、哪些参数爆显存”并不一定可靠。[AR03][AR04]

**反例二：代码编辑能力不等于算法创新能力**。NanoGPT-Bench 项目用带人类长期纪录的 NanoGPT speedrun 问题研究开放式优化。据其项目公布的初始实验，三种 Agent baseline 在各自 512 H100 GPU-hour 预算下，相比后续人类纪录进步所恢复的速度收益均不足 10%；其中 autoresearch 风格变体约 9.3%。项目还报告 Agent 将大部分预算花在 HP 调整，而人类纪录里相当多改进涉及算法变化。[AR12]

**这两个研究不能简单互相排序**：任务目标、奖励、可行动作、时间段、起始 baseline、预算核算均不同。它们共同提示的是：**自动实验比自动产生深层研究洞见更容易；一个更优秀的 Agent 不应只会反复试参数，还应提出高价值、可被证伪且能推广的机制创新。**
