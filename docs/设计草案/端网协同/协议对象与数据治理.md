## 9. 结构化协同协议

<a id="s9-1"></a>

### 9.1 设计原则

两侧 Agent 不应通过自然语言直接协商。协议应具备：

- 明确的消息类型；
- 明确的版本字段；
- 明确的事务 ID；
- 可验证的模型摘要；
- 可追踪的证据引用；
- 可重复的状态转移；
- 过期和撤销机制；
- 失败和回退分支。

<a id="s9-2"></a>

### 9.2 主要消息类型

```text
CAPABILITY_REPORT
MODEL_OFFER
MODEL_QUERY
EVALUATION_REQUEST
EVALUATION_RESULT
PREPARE_REQUEST
PREPARE_RESULT
READY
REJECT
COMMIT_REQUEST
COMMIT_ACK
MONITOR_REPORT
DEGRADE_ALERT
ROLLBACK_REQUEST
ROLLBACK_ACK
```

<a id="s9-3"></a>

### 9.3 模型切换事务

推荐的切换流程为：

```text
DISCOVER
    ↓
PROPOSE
    ↓
PREPARE
    ↓
LOCAL_VALIDATE
    ↓
READY / REJECT
    ↓
COMMIT
    ↓
ACTIVATE
    ↓
MONITOR
    ↓
ACCEPT / ROLLBACK
```

<a id="s9-4"></a>

### 9.4 状态语义

| 状态 | 含义 |
|---|---|
| `REGISTERED` | 模型已登记，但未证明适用于目标设备和场景 |
| `PROFILED` | 模型输入输出、资源和适用条件已描述 |
| `EVALUATING` | 正在执行模型、链路或系统评估 |
| `PREPARED` | 模型已下载/加载，但未激活 |
| `LOCAL_VALIDATED` | 本地契约和资源检查通过 |
| `READY` | 两端均满足共同生效条件 |
| `ACTIVATED` | 模型已经开始服务 |
| `MONITORING` | 正在收集部署后性能和资源指标 |
| `ACCEPTED` | 部署后验收通过 |
| `DEGRADED` | 性能退化，但尚未触发回退 |
| `ROLLED_BACK` | 已回退到旧模型或传统方案 |
| `REJECTED` | 因证据、兼容性、权限或资源不足而拒绝 |

“下载完成”不能直接等价于“可以运行”，更不能等价于“已经共同生效”。

## 10. 模型卡与证据对象

<a id="s10-1"></a>

### 10.1 模型卡

每个候选模型至少需要保存：

```json
{
  "model_id": "csi-compressor-v3",
  "version": "3.1.0",
  "model_location": "two-sided",
  "vendor_scope": "vendor-a",
  "input_contract": {
    "signal_type": "CSI-RS",
    "antenna_ports": 32,
    "band": "3.5GHz",
    "feedback_format": "type-II",
    "quantization": "int8"
  },
  "output_contract": {
    "output_type": "reconstructed-csi",
    "shape": "32xN"
  },
  "supported_scenarios": ["UMi", "indoor-office"],
  "resource_requirements": {
    "ue_memory_mb": 64,
    "ue_inference_latency_ms": 2.0,
    "max_power_mw": 500
  },
  "paired_models": ["decoder-v3.1.0"],
  "fallback_model": "legacy-csi-codebook",
  "evidence_refs": ["eval-2026-0012", "compat-2026-0021"]
}
```

<a id="s10-2"></a>

### 10.2 证据对象

证据不能只保存自然语言结论，而应保存：

- 证据 ID；
- 来源工具；
- 生成时间；
- 模型版本；
- 设备和配置；
- 场景；
- 指标和单位；
- 随机种子或测试批次；
- 有效期；
- 允许的用途；
- 是否为仿真、实测或人工说明；
- 是否经过独立验证。

```json
{
  "evidence_id": "eval-2026-0012",
  "evidence_type": "system_evaluation",
  "source": "evaluation_engine",
  "created_at": "2026-10-19T10:00:00+08:00",
  "model_version": "3.1.0",
  "scenario": "UMi",
  "device_profile": "ue-class-b",
  "metrics": {
    "throughput_mbps": 812.4,
    "feedback_overhead_ratio": 0.18,
    "inference_latency_ms": 1.7
  },
  "valid_until": "2026-10-26T10:00:00+08:00",
  "verified": true,
  "allowed_use": ["release_decision", "regression_check"]
}
```

<a id="s10-3"></a>

### 10.3 功能级模型注册

为了同时支持“需要什么能力”和“具体使用哪个实现”，模型注册表还需要维护功能级索引：

```json
{
  "functionality": "low-overhead-csi-feedback",
  "required_contract": {
    "max_feedback_overhead_ratio": 0.2,
    "max_inference_latency_ms": 2.0,
    "required_output": "reconstructed-csi"
  },
  "candidate_models": [
    "candidate-model-a",
    "candidate-model-b"
  ],
  "selection_policy": "evidence-and-cost-aware",
  "fallback": "legacy-csi-codebook"
}
```

功能级索引解决的是“需要什么能力”，模型 ID 解决的是“具体使用哪个实现”。Agent 必须保留二者之间的映射证据，不能因为功能名称相同就认为模型天然兼容。

## 11. 数据收集与隐私设计

<a id="s11-1"></a>

### 11.1 数据收集职责

| 数据任务 | BS Agent | UE Agent |
|---|---|---|
| 定义全局数据需求 | 负责 | 提供本地约束 |
| 定义本地采样字段 | 请求 | 执行和裁剪 |
| 判断是否允许上传 | 不可绕过 | 本地决定 |
| 上传聚合统计 | 负责协调 | 可上传授权结果 |
| 保存原始本地样本 | 不应默认要求 | 按本地策略保存 |
| 生成跨 UE 数据集 | 负责聚合 | 提供脱敏摘要或样本 |
| 训练/验证/测试划分 | 负责全局计划 | 提供本地分布约束 |
| 数据质量检查 | 全局统计 | 本地格式和完整性 |

<a id="s11-2"></a>

### 11.2 数据血缘

每个样本或聚合统计至少要绑定：

```text
样本/统计值
→ 采集实体
→ UE/小区标识范围
→ 时间戳
→ 场景和配置
→ 模型版本
→ 数据用途
→ 标签来源
→ 是否脱敏
→ 是否允许上传
→ 质量检查结果
```

<a id="s11-3"></a>

### 11.3 隐私边界

UE Agent 必须能够拒绝以下操作：

- 上传未经授权的原始信号；
- 上传可识别设备或用户的数据；
- 上传超过用途范围的数据；
- 继续执行已经撤销的数据采集任务；
- 使用本地数据训练未授权模型。

BS Agent 应优先使用：

- 聚合统计；
- 脱敏特征；
- 经授权的统计量或特征摘要；
- 受控的样本子集；
- 由 UE 明确授权的目标数据。

<a id="s11-4"></a>

### 11.4 联邦学习与隐私预算：暂不纳入第一版

联邦学习、差分隐私、隐私预算和参与者选择属于数据治理方向的后续扩展，不是当前双 Agent 生命周期闭环的必要条件。

第一版只保留与标准直接相关的约束：数据请求要说明用途、范围、来源、质量和成本；UE 能够拒绝未授权或超出本地策略的数据任务；LLM 不得绕过确定性权限门。后续若单独研究 FL/DP，应另立实验边界，并由确定性隐私会计器承担预算检查，不能把隐私决策交给 LLM。

<a id="s11-5"></a>

### 11.5 数据最小化决策

对于 CSI 压缩、波束预测等任务，Agent 应优先生成“最小必要数据计划”，而不是默认请求所有 UE 数据。例如：

| 任务 | 首选数据 | 默认不请求的数据 |
|---|---|---|
| CSI 压缩 | CSI-RS、参考信号观测、必要配置 | 精确位置、应用内容 |
| 波束预测 | 波束测量、历史波束选择、移动性摘要 | 原始用户业务内容 |
| 场景泛化评估 | 场景类别、设备能力、匿名化性能统计 | 可识别用户轨迹 |

Agent 可以提出最小化建议，但数据字段是否允许采集必须由 UE 本地策略和确定性权限门决定。
