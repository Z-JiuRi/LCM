### 22.4 四个值得拆源码和实验协议的项目

<a id="s22-4-1"></a>

#### 22.4.1 oh-my-pi：固定评测协议、可恢复研究状态和结果治理

1. **协议固定与 segment**：`autoresearch.sh` 在一个 segment 内被视为固定的 benchmark；显式新 segment 才变更准入条件或分数解释。这是应对 agent 偷换“考试题”的重要约束，但只靠提示文本并不能构成操作系统级权限隔离。
2. **工具即状态机**：`init_experiment` 定义会话、度量方向、路径约束；`run_experiment` 执行并结构化解析 METRIC、ASI；`log_experiment` 负责保留/丢弃/失败记录；`update_notes` 保存跨轮的想法与经验。这个设计把实验从对话转移到结构化可审计对象。
3. **日志治理**：`flag_runs` 能剔除可疑运行对基线/最佳值统计的干扰；scope deviations 记录“编辑了不应编辑的路径”；实现允许偏离但要求对保留偏离的实验进行解释。**记录偏离 ≠ 强制阻止偏离**，权限隔离仍需独立容器/只读数据集。
4. **噪声与重复实验**：低置信度时提示复测，confidence 是辅助量，不等同于独立 holdout 的统计证明。
5. **如何用于 AutoML**：将 HPO trial、代码变更、数据版本、种子、指标、资源预算统一入账；传统优化器做受控子空间搜索，Agent 负责实验假设与方向变更。

**适合改进**：只读 grader、随机化独立测试、预注册 benchmark contract、重复 seeds、消融与成本核算、强制审计和外部审稿环。[A02]

<a id="s22-4-2"></a>

#### 22.4.2 pi-autoresearch：可移植的研究 Harness 和可回放实验账本

`pi-autoresearch` 的核心数据平面为 `.auto/prompt.md`、`.auto/measure.sh`、`.auto/log.jsonl`，`checks.sh` 可独立验证代码正确性。Agent 可以在上下文 compaction 之后重读这些文件与 Git 继续实验；`finalize` 把保留的改动组织为便于审阅的独立分支；指标噪声使用 MAD 提示复测。相比“只靠 prompt 的夜间循环”，这是**生产研发工具所需要的恢复性、解释性和结果治理**。但 MAD 基于历史结果的估计不是正式的重复测量显著性检验，强度不应夸大。[A03]

<a id="s22-4-3"></a>

#### 22.4.3 AutoResearchClaw 与 ARIS：同是 end-to-end，审查位置不同

- AutoResearchClaw 强调**流程性**：23 阶段跨越选题、文献、方法、实验、论证、论文及审稿；在中途 PIVOT/REFINE，运行失败可 retry，部署中允许不同程度的人为介入。强项是工作流组织与产物统一；风险是流程完成不等于研究证明完成。[A05]
- ARIS 强调**模型间批判与证据**：执行者与另一模型家族 reviewer，citation/integrity/claim ledger 联动，并提供 Research Wiki。这样的设计有助于降低单一 Agent 的偏见，但模型间意见一致仍可能共同忽略实验错误，因而审查器应读原始 artifact 而不是只有结论摘要。[A06][A07]
- 选型：想要**可串联的科研工作流**优先评估 AutoResearchClaw/NanoResearch；要**证据/跨模型质量门控**重点研究 ARIS；要**多 Agent 科研搜索**研究 CORAL/SwarmResearch/Agora。项目介绍均不代替外部复现。

<a id="s22-4-4"></a>

#### 22.4.4 AIDE² 和 Agora：从“优化工作”走向“优化研究组织”

AIDE² 的外层每次实验直接修改 inner research harness 的策略和机制，再在任务组合上评价其**研究能力**。论文报告 8 天内 7 次连续改进，并在 4 个 held-out 基准上体现迁移。**不同材料中的 reward-hacking 百分比使用了不同试验集合/口径**：论文摘要写 55%→32%，早期作者博客写 63%→34%，报告保留两个口径，不将其合成同一个事实。其最关键的结论不是“递归变强已经无限成立”，而是**在固定任务/预算下可以测到 harness 的持续改进与一部分外推**。[A21][A40]

Agora 不依赖单一长期对话：每个 result、hypothesis、verification 都存入 Git DAG，使其它 Agent 能检查出处和贡献父节点。作者报告 13 个 worker 运行近 12 天，输出 1,703 项贡献、165 项对 95 个目标的交叉验证。但由于缺少严格匹配的等预算对照，不能断言“多人协作绝对优于单人”。[A14]

#### 22.5.1 Shopify Liquid、GPU Kernel、语音 Prompt 三个方向说明什么？

1. **Liquid 模板引擎**：优化目标不仅可以是 ML validation loss，还可以是 parse+render 速度和对象分配；应该有 correctness gates、不同 workload、硬件信息。Weco 索引整理了与公开 PR 对应的作者进展（53% 更快、61% 更少 allocations），**本报告没有对原始 PR 重跑 benchmark**。[A12]
2. **GPU kernel**：代码语义合法性和性能是双目标；更快但输出错误的 kernel 必须直接 reject。`RightNow-AI/autokernel` 是一个专用例子。[A12][A39]
3. **语音 Agent prompt**：文本/策略也可以是可编辑对象，但 evaluator 经常比训练 loss 更主观，需要固定语料、多场景和外部质量仲裁。[A12]

**共性**：任何能够将候选改动映射为**隔离、可重复、可比较的试验**的目标，都可以承载 autoresearch；**不代表所有开放科学问题都有单一可验证标量**。
