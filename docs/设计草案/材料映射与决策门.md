> **用途：设计追踪记录。** 本文将当前本地文献、标准材料和公开代码样例映射到设计选择，便于后续出现新证据时修正方案。它不是独立文献综述，也不替代原论文、标准条文、许可证或代码审查。
>
> 关联：[总体架构](LCMAgent架构设计草案.md)、[代码框架](代码框架与文件结构.md)、[实验方案](实验方案.md)。外部工具版本信息最后核验日：2026-10-20。

## 1. 仓库事实与证据规则

截至 2026-10-20，本仓库包含 `docs/分析/` 下的研究定位、协同设计、工具链调研，`docs/标准文件/` 下的标准/讨论材料，`相关工作/` 下的参考文献和逐篇解读，以及 `相关工作/codes/` 下的第三方公开代码检出。没有发现 LCMAgent 自有 `src/`、运行时、事务执行器、实验 episode、结果输出或自动化测试。

这只能说明“当前工作树未发现这些 LCMAgent 实现”，不表示团队其他目录、私有分支或外部工作站不存在实现。第三方代码 README 的报告数值不能当作本项目复现结果；找到代码不证明依赖安装、数据/权重下载、license 适用或可重复运行。

证据按来源分为：

- **标准/正式规范**：只支持其条文明确规定的实体、流程或约束；不能把项目 Agent 定义倒灌成标准协议。
- **原始论文**：说明已有研究和论文报告设置；是否复现需要本项目的运行记录。
- **作者/第三方仓库**：说明代码结构、声明依赖和仓库许可证；结果仍需按 commit、数据、权重、命令复现。
- **项目判断/草案**：本文件中的选型、目标、模块和实验设计，均是待验证方案。

## 2. 研究结论到设计选择

| 本地材料 | 可支持的判断 | 对方案的影响 | 尚不能据此声称 |
|---|---|---|---|
| [研究定位综述](../分析/LCMAgent相关论文综述与研究定位.md) | 双侧 LCM、工具编排、状态机、安全门、监测更新有先例；波束模型选择/适配和统计监测是直接相关工作 | 以“成本受限、会过期的证据如何驱动 LCM 决策”为候选问题；波束做主用例，CSI pair 做异构次用例；先与非 LLM 策略比较 | LLM/双 Agent 是必须或必然优于统计方法 |
| [工具链调研](../分析/LCMAgent实验数据与仿真工具链调研.md) | CSI 矩阵不等于可交互生命周期 episode；静态回放、仿真、软件 RAN、硬件在环和实测的主张边界不同 | Phase 0 用 lifecycle simulator；统一 time/cost/event schema；单选无线工具形成主链路 | 静态模型指标等于端到端业务收益 |
| [端网协同候选方案](端网协同候选方案.md) | 双侧状态/信息差异与本地验证值得作为候选场景，不能默认两侧各有 LLM | UE runtime 默认确定性；如需自治能力再把 UE Agent 作为消融研究 | UE Agent 已是系统架构定论 |
| [P09 WirelessOpsAgent](../../相关工作/论文详解/P09_WirelessOpsAgent.md) | APPLY/HOLD/RETRY/ESCALATE、执行状态与证据契约已有近邻 | 共享 validator 作为所有策略基础；比较时单列 unsafe/episode、unsafe/release、safe progress | action assurance 单独构成新颖性 |

| [P26 Beam Monitoring](../../相关工作/论文详解/P26_BeamModelSelection.md) 与 [P27 Beam Adaptation](../../相关工作/论文详解/P27_BeamLifecycleAdaptation.md) | 波束模型已有人做部署后监测、模型选择/适配与端网流程 | 主用例需对比其完整检测/选择能力，创新要落在成本受限证据/验收或配置变化等可量化差异 | “用于波束”“网络推荐、UE 测试”本身是新贡献 |

## 4. 外部工具路线的设计定位

| 层 | 候选 | 使用边界 | 设计门 |
|---|---|---|---|
| 控制面仿真 | 自有 Python episode simulator | D0 状态、成本、工具、恢复机制 | E0/E1 必须，不需要无线引擎 |
| 数据/信道 | DeepMIMO、QuaDRiGa 或固定本地 trace | 只由 `ChannelProvider` adapter 访问 | 在 beam/CSI 研究问题及数据权利明确后选一个 |
| 链路级 | Sionna PHY 或 MATLAB 5G Toolbox | KPI mapping 和动态链路效应 | 只在模型误差/feedback 要影响 BLER/throughput 时引入 |
| 系统级 | 5G-LENA + 适当 NR/O-RAN 扩展 | 多 UE、负载、时延、资源指标 | 定义 channel/model 输出到 system-level abstraction 的映射后再选 |
| 软件 RAN | OAI RF simulator + FlexRIC，或 srsRAN route | software integration、控制时序、日志 | 仿真稳定、需要栈级证据后择一路线 |
| 实测/HIL | 已授权数据/实验室平台 | 指定环境的设备、时延和功耗证据 | 明确设备、许可、频段、校准、测试条件；只作对应范围结论 |

官方文档状态在 2026-10-20 核验：[Sionna repository](https://github.com/NVlabs/sionna)、[DeepMIMO documentation](https://www.deepmimo.net/docs/)、[5G-LENA release notes](https://cttc-lena.gitlab.io/nr/html/md__2builds_2cttc-lena_2nr_2_r_e_l_e_a_s_e___n_o_t_e_s.html)。在研究实现启动时重新核对版本、系统要求、许可证和 API；不可把本文的时点版本视作永久锁定值。

## 5. 决策状态

### 5.1 当前暂定选择

- **研究对象**：有限预算与不确定状态下的无线 AI 生命周期证据决策；安全 gate 视为公用执行基础设施。
- **主用例顺序**：先单侧波束模型生命周期；CSI PairManifest 作为第二阶段差异化验证。
- **控制面**：先实现可确定重放的 Python simulator 和 deterministic executor；UE 组件是 deterministic Runtime。
- **策略顺序**：规则 → 统计监测/受控感知 → 固定工作流/主动证据 → 单网络侧 LLM planner；只有实验显示本地自治价值后再测 UE Agent。
- **无线环境**：D0 先行；随后选择一个可复现 beam/CSI 数据输入和一个模型评估主链；需要链路 KPI 时只接一款链路工具。
- **结果可信度**：独立 evaluator、hidden truth、paired scenarios、成本分项和安全指标双分母。

## 6. 进入实现前的必备产物

先做小范围立项冻结，不要求一次性解决所有未决事项：

1. 仓库实地清点：确认项目源码是否位于其他路径，数据/模型哪些实际存在且许可可用。
2. 一个 D0 trace：至少含一条 beneficial update、一条不可发布情况、一种测量成本与一种状态变化，验证环境有可观察 tradeoff。
3. `ObservationView` / `ActionProposal` / `EvidenceItem` / `EpisodeEvent` 的 schema 草案与隐藏真值隔离测试。
4. 同一 trace 上实现 B0 rule 和 B3 非 LLM active evidence baseline，校验 budget、事件和 evaluator 的共同语义。
5. pilot 后写实验注册文件：primary endpoint、预算层、统计计划、seed 列表和停止规则。

如果真实 episode 无法产生“少测有风险、全测有成本、错测有延误”的非平凡冲突，先修正场景/成本设计，不加 LLM。

## 7. 更新规则

每次改成“已决定”“已实现”“已验证”都附可审查依据：决定要有 ADR/实验计划；实现要指向代码和版本；验证要指向命令、commit、数据配置和结果。若原文献版本、标准修订或工具版本变化，只更新受影响决策，并记录修改日期与原因，不在不相关章节全量改写。
