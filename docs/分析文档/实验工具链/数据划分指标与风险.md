## 9. 第一版需要的数据量和划分

<a id="s9-1"></a>

### 9.1 不先追求大数据量

本项目第一篇论文的核心不是训练一个更大的无线模型，而是验证生命周期决策。因此，优先保证：

- 场景和设备配置覆盖足够；
- 故障注入覆盖清楚；
- episode 数量可以支持置信区间；
- 训练/开发/测试严格隔离；
- 每个错误动作都有可解释原因；
- 基线使用相同数据、工具和预算。

比起大量随机 CSI，少量但结构清晰的场景和完整动作轨迹更有价值。

<a id="s9-2"></a>

### 9.2 建议的数据划分

按以下单位切分，而不是随机切单个样本：

- 场景区域；
- 移动轨迹；
- 设备配置；
- 模型版本组；
- 故障类型；
- 工具错误模板；
- 时间窗口。

同一射线追踪场景的空间邻近点不能同时进入训练和最终测试；同一故障模板的轻微改写不能同时进入开发和测试；同一模型权重的重复报告不能伪装成独立样本。

<a id="s9-3"></a>

### 9.3 推荐的最小 episode 组成

每种关键故障至少应有：

- 正常发布；
- 证据缺失；
- 证据过期；
- UE 能力不足；
- 版本不匹配；
- 数据权限拒绝；
- 下载或准备失败；
- 单侧激活成功、另一侧失败；
- 激活后业务 KPI 退化；
- Agent 或工具超时。

每类故障应改变初始观测、预算或时序，而不是简单复制同一条模板。

## 10. 需要测什么指标

<a id="s10-1"></a>

### 10.1 Agent/生命周期指标

- 正确发布率；
- 错误发布率；
- Unsafe APPLY Rate；
- 版本不匹配率；
- 单侧激活率；
- 回退成功率；
- 恢复时间；
- 过期证据使用率；
- UE 本地拒绝率；
- 不必要补测率；
- 每个 episode 的工具调用次数和数据量。

<a id="s10-2"></a>

### 10.2 无线模型指标

- NMSE；
- GCS 或相关性；
- BER/BLER；
- CSI 反馈比特数和空口开销；
- 反馈延迟和信息年龄；
- 模型推理时延；
- 参数量、内存和计算量；
- 场景外泛化。

<a id="s10-3"></a>

### 10.3 系统和设备指标

- 吞吐量；
- 业务时延；
- 可靠性/违约率；
- PRB 或其他无线资源使用；
- UE CPU、内存和功耗；
- BS 计算和存储；
- 模型下载量；
- 业务中断时间；
- 切换期间性能损失。

NMSE 不是吞吐量，CSI 重构误差也不是自动的端到端业务收益。若论文声称“系统收益”，必须有从模型输出到链路/系统 KPI 的可执行映射。

<a id="s11"></a>

## 11. 基线和消融

<a id="s11-1"></a>

### 11.1 最低基线

| 基线 | BS | UE | 作用 |
|---|---|---|---|
| B0 | 固定规则/传统策略 | 传统本地检查 | 非 Agent 基线 |
| B1 | 单 BS Agent | 被动执行 | 检验 UE 本地组件是否必要 |
| B2 | BS Agent | 确定性 Runtime | 推荐主方案 |
| B3 | BS Agent | 轻量 UE Agent | 检验 UE 侧规划是否有额外价值 |
| B4 | 全知 Oracle | 全知 | 估计上限，不作为可部署方案 |

所有基线必须使用相同的：

- 候选模型；
- 初始观测；
- 工具集合；
- 数据预算；
- 发布窗口；
- 回退机制；
- 最终评价器。

<a id="s11-2"></a>

### 11.2 关键消融

1. 去掉 UE 本地能力检查。
2. 去掉模型配对检查。
3. 去掉证据时间戳和过期判断。
4. 去掉主动补测，改为固定测试序列。
5. 去掉在线运行后验收。
6. 去掉确定性执行门，只使用 Agent 输出。
7. 去掉回退控制器。
8. 让 UE 使用完整 LLM，测量额外收益与成本。
9. 只看 NMSE，不看业务 KPI，作为不完整评价对照。
10. 用第二个无线用例替换 CSI，检验架构是否具备可迁移性。

## 14. 主要风险和数据质量检查

<a id="s14-1"></a>

### 14.1 标签泄露

答案、故障真因、目标测试结果、正确发布动作和回退标签不能进入 Agent 的提示或检索库。按字段权限切分，不要只按文件切分。

<a id="s14-2"></a>

### 14.2 空间泄露

同一射线追踪场景的相邻位置如果分到训练和测试两侧，可能高估泛化。按场景区域、轨迹和时间组划分。

<a id="s14-3"></a>

### 14.3 模型输入不一致

检查：

- 实部/虚部顺序；
- 天线和子载波顺序；
- 归一化；
- DFT/角域变换；
- 反馈维度；
- 量化；
- 训练和推理框架；
- 数据单位。

<a id="s14-4"></a>

### 14.4 时间冻结

仿真等待 Agent/API 时，环境是否继续变化必须明确。否则会错误地把长推理时间当作零时延。

<a id="s14-5"></a>

### 14.5 仿真器自洽性

如果信道由某个工具生成，再由同一工具或同一模型计算结果，实验只能证明该仿真体系内部自洽。应至少增加：

- 不同场景参数；
- 不同信道模型；
- 时间/空间留出；
- 噪声和反馈丢失；
- 另一个实现或实测数据的小规模交叉验证。

<a id="s14-6"></a>

### 14.6 许可证和数据授权

代码开源不等于数据、权重和场景文件可以任意再分发。需要登记：

- 软件许可证；
- 数据访问条件；
- 权重许可；
- 实测数据使用范围；
- 是否允许公开发布样本；
- 是否允许上传给外部 LLM/API。
