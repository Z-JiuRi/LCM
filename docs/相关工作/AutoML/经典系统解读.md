## 5. 经典 AutoML 系统的论文深度解读

本节统一使用：**研究问题 → 方法机制 → 实验/论文结论 → 价值 → 局限 → 适用于 Agent 的启示**，避免将产品功能介绍误当成学术贡献。

<a id="s5-1"></a>

### 5.1 Auto-WEKA：CASH 问题的标志性系统

**论文**：Thornton et al., *Auto-WEKA: Combined Selection and Hyperparameter Optimization of Classification Algorithms*，KDD 2013。[R02]

- **核心问题**：人工流程通常先选择模型族，再单独调参；但算法选择和调参会相互影响，分开处理可能错过优秀组合。
- **方法**：将算法类型与特定模型的条件超参数编码在统一配置空间，用序贯模型优化技术跨模型族寻优。包含特征选择与分类模型等候选配置。
- **意义**：AutoML 不是“对一个模型调参”，而是搜索结构化的**算法—预处理—参数联合空间**。
- **局限**：复杂管线会使条件空间膨胀，搜索过程依赖定义良好的离线评估，难覆盖需求理解和数据治理。
- **Agent 启示**：让 Agent 生成结构化 CASH 搜索空间与约束，而不是直接生成未经验证的模型排行榜。

<a id="s5-2"></a>

### 5.2 auto-sklearn：元学习、Bayesian Optimization 和 Ensemble

**论文**：Feurer et al., *Efficient and Robust Automated Machine Learning*，NeurIPS 2015。[R03]

**关键机制**：

1. 用 scikit-learn 风格的组件形成分类器、特征预处理和数据预处理的联合搜索空间；
2. 根据历史数据集的元特征进行配置 warm start；
3. 用 SMBO 寻找表现好的候选；
4. 利用搜索过程中已经训练的模型构建集成，而不是只保留最终单一胜者。

**原论文结论**：在超过 100 个不同数据集上获得有竞争力的结果，元学习和集成的贡献通过消融得到分析。论文核心不是宣称“任何数据集都最优”，而是在非专家可用性与稳健性之间取得工程成果。

**Agent 启示**：Agent 的历史经验不应只存放文字型“总结”，还应包含**数据画像 → 候选配置 → 成本 → CV 结果 → 失败类型**的结构化记录；编排层可将历史候选传给优化器形成 warm start。

<a id="s5-3"></a>

### 5.3 Auto-sklearn 2.0：连 AutoML 的配置方式也要自动化

**论文**：Feurer et al., *Auto-Sklearn 2.0: Hands-free AutoML via Meta-Learning*，JMLR 2022。[R16]

**要点**：PoSH（Portfolio Successive Halving）结合模型配置组合与 bandit 式预算分配；meta-learning 不必总依赖显式数据元特征。作者指出 AutoML 框架自身通常有大量开关与元参数，使用者可能根本不知道如何设置，因此提出更趋向 hands-free 的设计。

**启示**：Agent for AutoML 的第二层任务可看作“为 AutoML 选择合适配置”的 meta-controller。这个思想也意味着**再增加一层 Agent 决策不一定总会提升质量**：如果 AutoML 2.0 已可以自动做的决策被 LLM 改为主观决策，可能带来额外波动与成本。

<a id="s5-4"></a>

### 5.4 Hyperband 与 BOHB：何时训练、训练多久，比采样方法同样重要

**论文**：Li et al., *Hyperband: A Novel Bandit-Based Approach to Hyperparameter Optimization*，JMLR 2018（部分引文与预印本年份写 2017，本文以期刊页面 2018 为准）；Falkner et al., *BOHB: Robust and Efficient Hyperparameter Optimization at Scale*，ICML 2018。[R04]–[R05]

- Hyperband 核心是资源调度，而不是训练模型本身。
- BOHB 把更有信息的候选建议与资源分配结合起来。
- 对 Agent 来说，“执行一次实验”不是原子行为，还必须包含资源请求、checkpoint、早停与失败恢复。
- 推荐让确定性的 scheduler 分配 GPU，Agent 只在有证据时修改搜索范围；避免 LLM 每个 trial 都重新随意设定预算。

<a id="s5-5"></a>

### 5.5 TPOT：用遗传程序搜索可组合管线

**论文**：Olson & Moore, *TPOT: A Tree-based Pipeline Optimization Tool for Automating Machine Learning*，AutoML Workshop / PMLR 2016。[R06]

**方法**：把特征处理器、估计器等操作组合成树或程序表示，用遗传编程执行变异、交叉与筛选。相较固定模板，搜索空间更接近“程序合成”。

**价值**：为后来的“Agent 直接搜索代码”提供历史类比：二者都在结构化/半结构化程序空间搜索。**区别**在于 TPOT 的操作符和语法可被强约束，而 LLM 自由生成代码的表达力更高、验证难度也更高。

<a id="s5-6"></a>

### 5.6 AutoGluon-Tabular：强基线通常来自组合，而不只来自调参

**论文**：Erickson et al., *AutoGluon-Tabular: Robust and Accurate AutoML for Structured Data*，arXiv 2020；官方文档持续维护。[R07], [R38]

**机制**：自动类型处理、多个模型族、bagging、multi-layer stacking、加权集成、预设质量档位；时间预算驱动的训练与部署偏好。原论文在 50 个分类/回归任务上比较多种系统，强调模型组合的收益。

**适用**：表格分类、回归；尤其适合作为 Agentic AutoML 的 baseline 引擎。**重要注意**：

- `best_quality` 常牺牲训练时间、预测延迟或磁盘空间；
- 当前文档有 `extreme_quality` 及针对新表格基础模型的配置，版本会更新；
- 某些附加基础模型有单独许可或商用限制；
- Agent 应通过官方 API 读取真实可用 preset，而不是假设每个部署环境都支持。

**Agent 启示**：用户仅说“给我最佳模型”时，Agent 应确认是追求 AUC、P99 延迟、成本还是可解释性，否则“最优”没有完整定义。

<a id="s5-7"></a>

### 5.7 Auto-PyTorch：把多保真 HPO 引入 AutoDL

**论文**：Zimmer et al., *Auto-PyTorch: Multi-Fidelity MetaLearning for Efficient and Robust AutoDL*，TPAMI 2021。[R08]

**核心**：把神经网络结构与训练超参数联合优化，并结合多保真搜索、warm-start portfolio、集成，兼顾 AutoML 与深度学习架构优化。

**启示**：AutoDL 场景下 Agent 生成训练程序时，必须严格记录数据增强、网络、optimizer、scheduler、epoch、精度与硬件配置；否则无法分离“Agent 规划更好”与“实际训练资源更多”。

<a id="s5-8"></a>

### 5.8 FLAML：搜索算法需要显式考虑 trial 代价

**论文**：Wang et al., *FLAML: A Fast and Lightweight AutoML Library*，MLSys 2021。[R10]

**问题**：资源小、时间短场景下，昂贵的大规模复杂搜索可能不划算。

**机制**：通过考虑估计器、训练数据样本规模、参数配置等对时间和损失的联合影响，实现相对轻量的自适应搜索。

**适用**：CPU 环境、快速原型、强预算约束、很多中小规模表格任务。**Agent 启示**：可把 `time_budget`、`metric`、`task` 等确定性约束传给 FLAML，Agent 只在上层决定具体任务与数据切分。官方 `AutoML.fit` 的 `time_budget` 参数以秒为单位。[R39]

<a id="s5-9"></a>

### 5.9 Optuna / SMAC3 / Ray Tune：通用优化器与调度器

- **Optuna**：KDD 2019，define-by-run 的目标函数式搜索、trial pruning、易于嵌入 Python 应用。适合定制模型或 Agent 自定义实验，但不自动处理全部特征工程。[R14]
- **SMAC3**：JMLR 2022，面向复杂超参空间、算法配置等的 BO 软件框架，提供多种配置 facade。[R11]
- **Ray Tune**：分布式实验调度与搜索执行平台，可配合 ASHA 等提前停止低潜力 trial；适用于实验并发、资源管理和任务恢复。[R15], [R40]

三者在 Agent 项目中最好抽象成统一的 **Experiment Scheduler 接口**，其输出应包含 trial ID、配置、运行状态、指标、时间、资源、错误、artifact 路径，而不是把模型的终端 stdout 整块传给 LLM。

<a id="s5-10"></a>

### 5.10 H2O AutoML：企业实践中的流程化基线

H2O AutoML 面向标准监督学习，具有若干经典模型与 stacked ensemble、排行榜、训练时限或模型个数控制。官方文档指出：若只靠 wall-clock 限制终止，运行时浮动会影响复现；采用固定 `max_models` 等配置有助于复现稳定性（实际仍受模型、硬件和随机性影响）。[R41]

**重要启示**：把“实现自动化”与“实验能否重复”当成两项不同的质量指标；AutoML agent 的良好演示可能来自一次幸运运行。

### 5.11 系统/组件快速选型表

| 项目 | 研究/产品定位 | 优点 | 重点局限 | Agent 最佳结合方式 |
|---|---|---|---|---|
| Auto-WEKA | CASH 经典研究 | 问题形式清晰 | 现代大规模工程生态相对弱 | 参考条件搜索空间建模 |
| auto-sklearn | 经典 sklearn AutoML | 元学习、BO、ensemble | 版本依赖、环境和资源成本 | 受控管线搜索引擎 |
| auto-sklearn 2.0 | hands-free AutoML | 自动配置策略 | 环境和任务范围约束 | 强制 baseline，验证 Agent 增益 |
| TPOT | GP 管线搜索 | 程序组合、可搜索预处理 | 计算成本、管线有效性校验 | 结构化程序空间研究 |
| AutoGluon | 多模型集成 AutoML | 表格基线强、API 简单 | 模型体积、延时、许可依赖 | 默认表格建模引擎 |
| FLAML | 成本敏感 AutoML | 轻量、预算友好 | 复杂任务需人工扩展 | CPU/低预算执行器 |
| Auto-PyTorch | AutoDL | 多保真与架构/训练联合优化 | GPU 资源、工程复杂度 | 深度任务受控搜索 |
| Optuna | 通用 HPO | 灵活、良好可扩展性 | 需自行实现任务和评价 | 自定义目标的搜索后端 |
| SMAC3 | 模型化 HPO | 条件空间、配置优化 | 调参与框架集成成本 | 搜索实验研究后端 |
| Ray Tune | 分布式调度 | 资源、并发、ASHA | 需要配套 Trainable/存储 | 执行与调度层 |
| H2O AutoML | 端到端常规模型 | 内建 leaderboard/ensemble | 任务与平台约束 | 交叉验证基线/备选引擎 |

## 2. 经典 AutoML：什么被反复证明了

（论文与引用数见 `papers.md` A/B 组。）

- **预算控制 > 代理模型精巧度**。Hyperband 把 HPO 变成无限臂赌博机并逐层淘汰，BOHB 在同一调度上叠 TPE，FLAML 把"低资源"当第一目标并在同等或低 1–2 个数量级的预算下超过当时第一梯队库。三者的共同点是对**代价**建模，而不是对**响应面**建模。
- **热启动几乎总是最大的单点收益**。auto-sklearn 2.0 用"免元特征"的元学习 + bandit 预算分配，专门解决"刚性时间限制 + 大数据集"。这条线索在 2026 年被反过来用作证伪工具（§4），说明它是真效应。
- **集成与后处理常压过搜索**。AutoGluon-Tabular 摘要原话是"多层组合多模型比寻找最优模型更好地利用了分配的训练时间"（原句：our multi-layer combination of many models offers better use of allocated training time than seeking out the best）。同一篇还顺带给 TPOT/H2O/AutoWEKA/auto-sklearn/Google AutoML 做了横向评测。AMLB 这类跨框架基准的出现，反映了社区对"结论依赖评测协议"的自觉（推断）。
- **NAS 的收敛形态是"搜索空间工程"**。从 Zoph & Le 的 RNN 控制器，到 ENAS 的权重共享把算力降一个数量级，到 AutoML-Zero 从原始算子进化算法，"架构搜索"的进展主要来自**缩小或重构空间**，而不是把搜索器变聪明。
- **领域内已有 AutoML 落地证据**：CSI 反馈场景定制编码器（Auto-CsiNet, TWC）、AI-RAN 主动流量预测的智能体化架构搜索、零接触网络安全（TNSM）。这些是"AutoML 在无线侧确实被用过"的存在性证明，但都不是生命周期决策。
