## 17. 开放研究问题与论文选题

以下选题是本报告根据已核查论文与系统痛点综合提出，属于**潜在研究方向**，不代表已有实验能证明其结果。

<a id="s17-1"></a>

### 17.1 研究方向一：Learning-to-Orchestrate AutoML

**问题**：给定数据画像、模型经验、计算预算，如何训练 controller 判断何时调用 AutoGluon、FLAML、HPO、基础模型，何时停止？

**方法草案**：采用上下文 bandit、offline RL 或偏好建模；状态包含 `meta-features + elapsed budget + performance curve`，动作包含 `choose_engine/expand_search/stop`，奖励根据最终质量-成本约束计算。

**论文贡献潜力**：从算法级调参升级到系统级策略调度，特别适合跨任务预算差异大的场景。

**难点**：不同 engine 的试验成本差距、历史任务分布偏差、训练/评估任务穿透。

<a id="s17-2"></a>

### 17.2 方向二：RAG + Structured Experiment Memory

**问题**：文献式 RAG 与结构化历史实验对下一次试验建议哪个更有效？经验需要存储哪些字段？

**核心实验**：对比 `no memory / text-only summary / numeric nearest neighbor / hybrid retrieval / learned reranker`，固定底座 LLM 和预算。

**指标**：best-so-far、无效方案复现次数、转移到 OOD 数据时的负迁移比例、agent 上下文长度。

<a id="s17-3"></a>

### 17.3 方向三：Leakage-Aware AutoML Agent

**问题**：Agent 会不会更擅长提高验证分数，却更容易发现看似可用的后验泄漏信号？

**设计**：使用合成与真实数据的可控数据泄漏注入，构造时序/实体泄漏、多表 join 泄漏、重复目标编码等测试。

**创新**：搜索收益与审计能力联合最优化，将“拒绝高分但不合法的模型”定义为高质量行动。

<a id="s17-4"></a>

### 17.4 方向四：Uncertainty-Aware Agent Planner

**问题**：Agent 无法知道自己下一次修改有多大概率提升，能否用不确定性/expected value of information 指导工具调用？

**方法**：校准的收益分布估计、历史经验近邻、搜索试验置信区间、剩余预算机会成本。

**评价**：在难度可控的实验集上测量 calibration、ranking ability、Regret under budget。

<a id="s17-5"></a>

### 17.5 方向五：Search Tree + BO Hybrid

**问题**：代码空间修改很灵活但昂贵；BO 有效率但受限于结构化空间。能否把“模型结构级动作”和“结构内数值调参”分层优化？

**想法**：Agent 生成有限的新模型/特征操作节点；每个节点由 Optuna/SMAC 在结构化子空间调参；以标准化的父子候选成绩决定后续资源分配。

**关键对照**：固定 code search only、HPO only、hierarchical hybrid 的相同算力和 token 成本。

<a id="s17-6"></a>

### 17.6 方向六：Policy-Trained Small ML Agents

**动机**：ML-Agent 与 DeepAnalyze 说明训练型策略路线已经有实证探索。[R28]–[R29]

**研究问题**：小模型在有限工具 API 下，通过正确的交互式反馈设计，能否以更低成本完成标准表格建模调度？

**难点**：奖励稀疏、依赖训练时被隐式污染的数据、长任务信用分配和异常动作的安全性。

<a id="s17-7"></a>

### 17.7 方向七：多目标 AutoML 的人类意图对齐

**问题**：用户只说“最好的模型”，实际偏好可能是低延时、低成本、较好的召回，或者强可解释性。Agent 如何在不滥用隐式假设前提下得到可审计的效用权重？

**方案**：通过约束优先级排序、少量人类偏好比较、Pareto front 展示，记录用户确认的权衡。

**结果验收**：在真实业务约束变动情境中衡量需求理解的准确率与错误上线决策次数。

<a id="s17-8"></a>

### 17.8 方向八：因果归因与反事实评估

**问题**：一次 agent 试验同时更换特征、模型族和验证策略，无法知道是哪一步产生效果。

**方法**：因果化实验日志、最小修改单位、对照重放、同 seed 控制、必要时 do-operator 风格的组件替换实验。

**现实价值**：把 Agent 的“自然语言解释”变为有实验支持的因果证据链。

<a id="s17-9"></a>

### 17.9 方向九：持续学习与非平稳任务流

**问题**：企业数据分布和标签定义持续变化；历史高分配置可能在未来任务失效。

**研究**：基于漂移检测的 meta-memory 衰减、task embedding、在线资源调度、回滚机制；衡量长期累计成本与任务性能。

<a id="s17-10"></a>

### 17.10 方向十：开放式 Agent 的安全评价套件

**问题**：当前很多 benchmark 关注成绩，而工程 Agent 还能安装包、执行脚本、访问文件与外部 API。

**方案**：高可信模拟环境内注入提示攻击、恶意 README、危险 shell 命令和外泄请求，统计策略违规率、拒绝率与恢复能力。

**验收**：在不牺牲合法任务成功率的前提下减少安全事件，而不是仅衡量语言模型能否口头识别恶意提示。

## 6. 机会地图

| 类型 | 内容 | 现有覆盖 | 需要的证据 |
|---|---|---|---|
| `benchmark gap` | 预算**强制执行**与选型路径同构的 AutoML 对比协议；决策级指标套件 | `2608.07303` 给了 checklist，`2602.22442` 给了四维框架，但都没有成为标准 | 可复现的协议 + 参考实现 + 跨系统复测 |
| `mechanism gap` | 为什么 agent 在 L3 有效？是空间扩大、先验注入，还是语义接地？ | 只有 `2609.16309` 做了增益分解（+0.6%），粒度粗 | 三因素消融：空间规模 / 先验质量 / 语义信息 |
| `system gap` | 有控制延迟、有资源竞争、动作不可回退的环境下，agent 决策是否仍有效 | 无线侧仅 `2609.14517` 量化了延迟对纠正策略的摧毁性 | 带延迟注入的闭环实验 |
| `negative-result` | 系统化的 agent 必要性证伪（含 harness 消融、先验消融） | `2606.21641`、`2609.40303` 各覆盖一角，都是单场景 | 多场景重复 + 预注册指标 |
| `crowded but open` | 代码级管线搜索（P2） | AIDE/SELA/I-MCTS/AutoML-Agent/MLE-STAR/R&D-Agent/MLZero/iML 已很密 | 若要进入，需换问题而非换脚手架 |

## 8. 待决策与下一步

**待决策（需数据或 pilot 决定）**

- D1：本项目的对照基线取"固定阈值 + 序贯检测"还是"CMAB/BO 规划器 + 序贯检测"？AutoML 证据倾向后者更公平（`2603.24647`）。
- D2：决策级指标采用 `2602.22442` 的四维框架，还是自定义"证据采购效率 + 误发布成本"二维？
- D3：是否需要引入控制延迟注入作为强制实验条件（`2609.14517` 的做法）？

**建议的三个最小实验（按性价比排序）**

1. **预算执行审计**：把现有人工/脚本基线放进"名义 60s、实际不强制"vs"外部强制 deadline"两种协议，量化结论差异幅度。这一步不需要实现 agent，成本最低，且能复现 `2608.07303` 的效应量级。
2. **agent vs 经典优化器在离散决策上的分工实验**：同一执行基础设施下，(a) 全 agent、(b) 经典优化器 + 人工先验、(c) agent 造候选空间 + 经典优化器搜索（P3），三方对比。
3. **先验消融**：把默认策略/领域知识从 agent 提示与初始解中移除，测性能跌幅。若跌幅 >80%，说明主张应改写为"先验有效"。

**不建议现在做**：再实现一个 P2 类多 agent 管线搜索系统——该格已过度拥挤（§3、§6），且 harness 增益本身受到挑战。
