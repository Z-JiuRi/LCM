## 12. 典型运行流程：以 CSI 为例的模型退化与切换

<a id="s12-1"></a>

### 12.1 触发

UE 和 BS 侧监测到：

- CSI 重构误差持续升高；
- CSI 反馈开销没有下降到预期水平；
- 推理时延超过预算；
- 吞吐量低于传统基线；
- 新小区或新频段上的性能明显退化。

<a id="s12-2"></a>

### 12.2 BS Agent 处理

BS Agent 读取：

- 当前模型和版本；
- UE 能力和本地资源状态；
- 目标小区和邻近小区统计；
- 候选模型注册信息；
- 已有评估证据；
- 当前维护窗口和切换预算。

然后判断问题更接近：

- 场景漂移；
- 训练数据分布变化；
- 模型版本失配；
- UE 配置变化；
- 输入格式变化；
- 资源不足；
- 监测数据异常。

<a id="s12-3"></a>

### 12.3 候选动作

```text
A. 继续观察
B. 增加数据采集
C. 仅做 BS/网络侧兼容适配
D. BS 侧微调
E. UE 侧微调
F. UE 与 BS 双侧更新
G. 切换到场景模型
H. 回退传统 CSI 方案
```

<a id="s12-4"></a>

### 12.4 UE Agent 本地检查

对每一个候选模型，UE Agent 检查：

- 输入字段是否齐全；
- 天线端口和频段是否匹配；
- 反馈格式是否匹配；
- 模型量化格式是否支持；
- 内存是否足够；
- 推理时延是否满足要求；
- 功耗是否在预算内；
- 本地数据策略是否允许采集或微调；
- 本地回退模型是否存在。

<a id="s12-5"></a>

### 12.5 发布判定

只有在以下条件同时满足时才允许共同激活：

```text
输入输出契约兼容
AND
两侧模型配对正确
AND
UE 本地资源满足
AND
目标场景评估通过
AND
旧场景回归没有超过损失阈值
AND
切换成本在预算内
AND
回退路径已准备
AND
两侧都返回 READY
```

<a id="s12-6"></a>

### 12.6 CSI 评估链路：研究实现，不是标准工具链

在 CSI 用例中，模型评价应放回完整的通信流程，而不是只比较 NMSE。实现时可以将工具按以下职责组织，但不预设具体 API 名称，也不把它们写成标准要求：

```text
候选模型/模型卡
    ↓
输入输出与两侧配对检查
    ↓
信道估计 → CSI 压缩/预测 → 量化与反馈
    ↓
gNB 重建 → 预编码/调度
    ↓
链路 KPI、系统 KPI、推理/反馈/切换成本
    ↓
带证据引用的评估与发布报告
```

其中，兼容性检查、性能仿真、结果查询和报告生成应当是可审计的确定性工具；BS Agent 负责决定下一项检查或补测，UE Runtime 负责提供本地能力、资源和可采数据边界。标准检索可以作为离线知识库能力，但不是运行时 CSI 工具链的必要节点。

CSI 工作流至少应显式表示：

```text
信道估计 → CSI 压缩 → 量化 → PUCCH/PUSCH 反馈
→ gNB 重建 → 预编码/调度 → 链路与系统 KPI
```

这样可以把“模型精度很好”转换为可检查的端到端问题：压缩收益是否抵消了反馈、推理、重建和部署开销。

## 13. 生命周期状态机设计

<a id="s13-1"></a>

### 13.1 全局状态机

```text
REGISTERED
    ↓
PROFILED
    ↓
EVALUATING
    ├── 证据不足 → NEED_MORE_EVIDENCE
    ├── 不兼容 → REJECTED
    └── 评估通过 → PREPARING
                         ↓
                 UE_LOCAL_VALIDATION
                         ├── 失败 → REJECTED
                         └── 通过 → READY_WAIT
                                         ↓
                                  JOINT_COMMIT
                                         ├── 一端失败 → ABORTED
                                         └── 成功 → ACTIVATED
                                                      ↓
                                                  MONITORING
                                                      ├── 正常 → ACCEPTED
                                                      ├── 可适配 → ADAPTING
                                                      ├── 可切换 → SWITCHING
                                                      └── 严重退化 → ROLLING_BACK
```

<a id="s13-2"></a>

### 13.2 状态转移必须带条件

每次状态转移需要记录：

- 当前状态；
- 目标状态；
- 触发原因；
- 触发者；
- 证据引用；
- 必需验证；
- 当前模型版本；
- 目标模型版本；
- 事务超时；
- 失败后的回退状态。

<a id="s14"></a>

## 14. 失败场景与处理策略

<a id="s14-1"></a>

### 14.1 BS 认为可用，但 UE 本地拒绝

原因可能是：

- UE 内存不足；
- 输入配置不匹配；
- 模型签名无效；
- 本地功耗预算不足；
- 本地隐私策略不允许采集数据。

处理方式：

```text
UE 返回 REJECT
→ BS 记录具体原因
→ Agent 重新选择候选动作
→ 不得把拒绝改写成 READY
```

<a id="s14-2"></a>

### 14.2 UE 已准备，但 BS 状态发生变化

例如：

- 维护窗口结束；
- 目标模型被撤销；
- 小区负载突然变化；
- 另一项发布事务先完成。

处理方式：

- 检查事务版本和过期时间；
- 重新读取 BS 当前状态；
- 旧计划自动失效；
- 不允许使用过期计划直接提交。

<a id="s14-3"></a>

### 14.3 一侧激活成功，另一侧失败

这是双侧模型的关键风险。处理方式：

- 采用准备阶段而不是直接激活；
- 共同提交必须有事务 ID；
- 设定最大等待时间；
- 一侧提交失败时执行中止或回退；
- 记录半完成事务；
- 不将半完成状态报告为成功发布。

<a id="s14-4"></a>

### 14.4 模型运行性能下降

分级处理：

```text
轻微退化 → 增加监测
持续退化 → 采集补充数据
可解释漂移 → 特定场景微调
明显失配 → 切换候选模型
安全或业务风险 → 立即回退
```

<a id="s14-5"></a>

### 14.5 Agent 或 API 不可用

Agent 不可用时：

- 当前已激活模型继续运行；
- 快速控制器继续工作；
- UE 本地回退控制器保持可用；
- 不执行新的高风险模型切换；
- 恢复后重新检查证据和版本状态。
