## 11. 传统 AutoML 与 Agentic AutoML 全面对比

<a id="s11-1"></a>

### 11.1 一张表看全局

| 比较维度 | 传统 AutoML | Agentic AutoML | 更优选择依赖什么 |
|---|---|---|---|
| 用户交互 | 明确数据与固定参数/API | 可自然语言描述目标 | 需求歧义程度 |
| 搜索空间 | 参数/管线/架构结构化定义 | 工具调用＋开放式代码＋假设 | 开放程度 vs 控制要求 |
| 实验规划 | 采样器/优化器驱动 | LLM/策略提出试验方向 | 元经验、任务复杂性 |
| 统计效率 | 有历史优化器与早停机制 | 可利用语义知识，但可能做无效试验 | 目标函数结构与模型知识 |
| 稳健性 | 通常更可控 | 需要额外执行沙箱和约束 | 业务安全要求 |
| 自动数据理解 | 限定的自动类型推断 | 潜在更强的业务语义理解 | 数据字典/业务上下文 |
| 失败恢复 | 对既定异常的处理成熟 | 有潜力跨问题调试 | agent 的工具与诊断质量 |
| 可解释性 | Search logs、leaderboard | 计划/轨迹可读但未必真实因果 | 评价/审计机制 |
| 可复现性 | 相对容易固定参数/seed | 行动轨迹受 LLM 随机性影响 | replay/记录/锁版本 |
| 可扩展 | 预设模型家族 | 可探索新特征、新模型、新代码 | 评价可靠性/成本 |
| 总成本 | CPU/GPU 训练为主 | 训练+LLM+工具+返工成本 | 资源约束 |
| 典型陷阱 | 过小搜索空间、难配置 | 幻觉、泄漏、无谓试验、越权 | 验证护栏 |

<a id="s11-2"></a>

### 11.2 什么时候不需要 Agent

以下情况应优先采用传统 AutoML：

- 任务标准、标签明确、数据表结构稳定；
- 有固定的强 baseline，业务目标仅是提高若干百分点的建模质量；
- 内部安全策略不允许模型自动访问文件系统或执行临时代码；
- 预算严苛，额外的 LLM 调用与复杂编排很难回本；
- 需要极强的复现性、审计性、确定性调度；
- 只是把某个模型的学习率、层数、树深度调到合适区间。

此时把 Optuna/AutoGluon/FLAML 与正确的验证方案做好，通常比引入 agent 层更重要。

<a id="s11-3"></a>

### 11.3 什么时候 Agent 可能显著增加价值

- 用户只能描述业务目标，无法事先指定标签、切分方式和质量约束；
- 数据源来自多个业务系统，列语义需要数据字典/规则解释；
- 需要串联 SQL、Python、实验平台、模型仓库、部署系统；
- 代码运行失败的原因多样，存在动态修复价值；
- 可能需要新特征、数据清洗逻辑或自定义损失；
- 同一组织有海量相似历史实验，可支持案例推理；
- 工具/模型不断演化，固定 pipeline 难以覆盖。

这些是**Agent 可能提升效率的条件**，并不是性能保证。应通过[第 15 章](评测协议与增益归因.md#s15)的实验设计量化增益。

<a id="s11-4"></a>

### 11.4 推荐的混合式层级

```text
[人的目标与合规约束]                         ← 定义做什么、容许什么
            ↓
[LLM Planner / Task Interpreter]             ← 理解不完整的需求
            ↓
[Constraint Solver / Evaluation Designer]   ← 确定可评价和不泄漏
            ↓
[AutoML / NAS / HPO 内核]                    ← 精确搜索与执行
            ↑                       ↓
[Experiment Memory / RAG] ← [Structured Evaluator]
            ↑                       ↓
            └───── [Agent Reflection] ──────┘
                                    ↓
                          [Model Registry / Approval]
```

优先使用“**自由决策的 Agent + 严格约束的执行器**”。优化器内的每次 trial 不需要 LLM 审批；只有当出现连续性能平台期、模型族选择改变、复杂数据修复或预算再分配时，才调用高层 Agent。

### 20.2 关键争议的立场摘要

**争议一：Agent 会不会取代 AutoML 优化器？**  
没有充分证据证明普遍取代。结构化、可评价的 HPO/CASH 问题仍然适合 BO、Hyperband、集成与元学习；Agent 的价值主要在开放任务理解、外层编排和非标准动作生成。

**争议二：多 Agent 是否总比单 Agent 更强？**  
不是。需要比较在相同预算下独立角色是否真正提高规划覆盖度、工作并行度、验证独立性；如果只是增加对话轮次，可能放大错误与成本。

**争议三：Kaggle 高奖牌率等于真实企业建模能力吗？**  
不等于。公开竞赛容易存在历史知识、数据污染与特定排行榜优化；企业场景还有权限、漂移、隐私、延迟和运营约束。MLE-bench 是重要但不完整的代理目标。

**争议四：LLM Agent 可以代替交叉验证与测试集吗？**  
绝不可以。Agent 可建议选择正确验证方案，但评测器必须独立，随机化和数据切分必须严格执行。

**争议五：2026 的训练型 Agent 是否终结提示词工程？**  
尚无定论。ML-Agent 和 DeepAnalyze 展示了有意义的训练路线，但工具环境和规则约束仍关键，且训练轨迹质量、泛化和安全会成为更重要的研究问题。
