## 12. 推荐的四阶段实施路线

### Phase 0：生命周期控制面原型

**目标**：先证明 Agent 机制，而不是证明无线模型。

工具：

- Python；
- JSONL episode；
- 固定模型卡；
- 合成评估报告；
- 状态机和故障注入；
- BS Agent；
- UE Runtime；
- 独立评价器。

必须完成：

- 共同准备/激活/回退；
- 版本不匹配；
- UE 本地拒绝；
- 证据过期；
- 工具失败和重试；
- 统一指标和日志。

产出：可以回答“是否有双侧生命周期机制价值”，但不能回答“无线模型是否提升链路性能”。

### Phase 1：固定 CSI 模型和静态场景

推荐：

- CsiNet 或其他已有固定模型；
- 作者匹配测试数据；
- DeepMIMO 场景扩展；
- Python 数值评估工具。

必须验证：

- 模型和数据输入契约；
- 权重哈希和版本；
- 训练域/测试域划分；
- NMSE、相关性、反馈开销和推理时间；
- BS/UE 模型配对；
- 资源不足和版本切换。

### Phase 2：动态信道和链路级评价

选择一个：

- QuaDRiGa：优先研究移动性、时间相关性和过期 CSI；
- Sionna PHY：优先研究链路、反馈、噪声、丢失和端到端物理层；
- MATLAB 5G Toolbox：优先快速实现标准 NR 参考流程和交叉验证。

不要第一版同时使用三个链路工具作为主结果。可将一个作为主平台，其余作为 sanity check 或扩展实验。

### Phase 3：系统级和软件 RAN 集成

两条路线择一：

#### 路线 A：5G-LENA + ns-3 O-RAN

优点：

- 可重复；
- 适合多 UE/多小区；
- 便于测吞吐、时延、资源和切换；
- 可接逻辑模块和 RIC 记录。

缺点：

- 需要自己把模型输出映射到系统级行为；
- 不能直接当作完整真实 O-RAN；
- CSI 神经编解码的物理层细节不完整。

#### 路线 B：OAI RF simulator + FlexRIC

优点：

- 更接近软件 RAN 和协议栈；
- 可以产生真实软件日志、配置和控制时序；
- 便于后续接 SDR。

缺点：

- 构建、配置和版本成本较高；
- 对机器、内核、网络接口和组件兼容性要求高；
- RF simulator 不是真实传播；
- 需要额外开发模型和生命周期接口。

### Phase 4：授权实测或硬件在环

可选方式：

- DeepSense 等公开实测数据；
- OAI/srsRAN + SDR；
- COTS UE/gNB 测试床；
- 现有实验室 RAN 平台。

这一阶段主要验证：

- 实际推理和加载成本；
- 软件栈日志和动作生效时序；
- 真实设备资源和功耗；
- 仿真域到实测域的偏差。

没有实测时，论文可以诚实地写成“仿真和软件协议栈验证”；不能写成“真实网络部署验证”。

## 13. 哪条路线最适合当前项目

<a id="s13-1"></a>

### 13.1 推荐主路线

当前项目最稳妥的主路线是：

```text
Phase 0 控制面
  -> Phase 1 CsiNet + 作者数据/DeepMIMO
  -> Phase 2 Sionna PHY 或 QuaDRiGa 二选一
  -> Phase 3 5G-LENA + ns-3 O-RAN 或 OAI RFsim 二选一
```

推荐优先顺序：

1. **先做生命周期控制面，不等待真实 CSI 数据。**
2. **再接固定 CSI 模型和可验证数据。**
3. **如果研究的是过期和反馈时序，选 QuaDRiGa；如果研究链路效果，选 Sionna PHY。**
4. **如果研究多 UE/网络 KPI，选 5G-LENA；如果研究软件 RAN 集成，选 OAI RFsim。**
5. **实测作为增强证据，不作为第一阶段阻塞条件。**

<a id="s13-2"></a>

### 13.2 不推荐的路线

不推荐一开始同时做：

- Sionna RT；
- Sionna PHY；
- QuaDRiGa；
- DeepMIMO；
- MATLAB；
- 5G-LENA；
- ns-3 O-RAN；
- OAI；
- srsRAN；
- FlexRIC；
- 真实 SDR。

这会把研究变成平台集成项目，无法判断哪一部分产生了收益。工具越多不等于证据越强，反而会增加版本、单位、时间和数据格式不一致的风险。

## 15. 实验包目录建议

建议每个实验版本采用如下目录：

```text
experiment-release-v1/
  manifest.json
  configs/
    simulator.yaml
    model_registry.json
    device_profiles.json
    scenario_split.json
  data/
    channel_refs.jsonl
    model_evidence.jsonl
    runtime_states.jsonl
    episodes.jsonl
  agent_view/
  evaluator_private/
  tool_events.jsonl
  action_events.jsonl
  metrics/
  plots/
  logs/
  README.md
```

`manifest.json` 至少记录：

- Git commit；
- 仿真器版本；
- Python/MATLAB/PyTorch/CUDA 环境；
- 模型和数据哈希；
- 场景参数；
- 随机种子；
- 单位和坐标系；
- 许可证和访问限制；
- 训练/开发/测试划分；
- 是否仿真、重放、硬件在环或实测。

## 16. 最终建议

<a id="s16-1"></a>

### 16.1 数据层面的最小闭环

第一版论文至少需要完成：

```text
固定模型资产
  -> 可复现 CSI/信道数据
  -> 模型评估报告
  -> BS/UE 兼容性和资源状态
  -> Agent 补测/切换动作
  -> 状态变化和失败注入
  -> 独立验收与回退指标
```

<a id="s16-2"></a>

### 16.2 工具层面的最小闭环

优先实现：

1. Python 生命周期状态机。
2. CsiNet 或其他固定 CSI 模型的 only-test 评估。
3. DeepMIMO 或作者数据的严格场景划分。
4. Sionna PHY 或 QuaDRiGa 二选一。
5. 一个独立的模型兼容性和设备资源检查器。
6. 一个可注入失败、延迟和过期证据的发布模拟器。

<a id="s16-3"></a>

### 16.3 论文表述边界

如果没有真实 RF 或硬件在环，只能说：

- 在可控无线仿真中验证；
- 在指定数据和模型配置下验证；
- 在软件 RAN/RF simulator 中验证；
- 证明生命周期机制在实验环境内有效。

不能说：

- 已证明适用于商用网络；
- 已证明适用于所有 UE；
- 已证明降低真实网络功耗；
- 已完成真实 O-RAN 部署；
- 仿真 CSI 就等于真实现场 CSI。

## 18. 结论

对于 BS/UE 双 Agent 论文，实验数据的核心不是“找一个最大的无线数据集”，而是构造一个能够同时连接以下对象的可复现实验闭环：

```text
无线状态
  + 模型资产
  + 端侧资源和隐私事实
  + Agent 工具调用
  + 模型准备/激活/回退动作
  + 动作后无线和业务 KPI
  + 独立隐藏评价
```

当前最推荐的工具路线是：

```text
Python 生命周期仿真
  + CsiNet 固定模型
  + 作者数据或 DeepMIMO
  + Sionna PHY 或 QuaDRiGa（二选一）
  + 后续再接 5G-LENA/ns-3 O-RAN 或 OAI RF simulator
```

Sionna、QuaDRiGa、DeepMIMO、5G-LENA 和 OAI/srsRAN 不是互相替代的工具，而是分别位于传播/信道、链路、系统、软件 RAN 和实测层。第一篇论文应选择一个主平台，明确每个结果能够支持的主张，保留其他工具作为扩展或交叉验证。
