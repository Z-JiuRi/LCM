### 5.2 公开无线模型/数据资源

#### CsiNet 及相关 CSI 模型仓库

CsiNet 类仓库适合做第一版固定模型基线，因为有模型结构、预训练权重和 only-test 代码。它可以提供：

- 编码器/解码器模型；
- 固定压缩率；
- NMSE、相关性或 GCS 等模型层指标；
- 室内/室外等已有划分。

但它通常不能直接提供：

- 真实 UE/gNB 运行时；
- 反馈链路中的丢包、延迟和调度；
- 设备功耗；
- 模型发布、切换和回退事务。

因此 CsiNet 适合作为数值模型，不是完整端网实验环境。

#### DeepMIMO

DeepMIMO 的定位是把射线追踪场景转化为可复用、可配置的无线数据集。适合：

- 场景间泛化；
- 不同用户位置和天线配置；
- CSI、波束和路径相关学习；
- 训练域/测试域分离；
- 复现实验的参数化数据生成。

不适合直接承担：

- 动作改变后的网络闭环；
- 真实 UE 功耗和推理时延；
- 完整 O-RAN 控制流程；
- 未经额外处理的实时移动轨迹。

DeepMIMO 应被理解为“由射线追踪结果生成的场景化数据接口”，而不是现场测量数据。使用时必须记录场景版本、射线追踪来源、用户区域、天线、频率、采样和数据生成参数。

#### DeepSense 6G

DeepSense 6G 适合补充真实感知/通信多模态数据，例如位置、视觉、LiDAR、雷达或波束相关观测，具体以场景数据卡为准。它可以增强：

- 仿真到现实的比较；
- 多模态状态感知；
- 位置/环境与无线表现的关联；
- 预测与测量的差异分析。

它不应被默认称为完整 CSI、完整 NR 日志或可随意干预的数字孪生。每个场景的模态、坐标系、采集条件和访问许可必须单独核对。

#### WirelessBench、TeleLogs 和 TeleLogsAgent

这些资源更适合 Agent 控制面，而不是无线物理层：

- WirelessBench：无线任务、工具调用和多步决策基准种子；
- TeleLogs：网络运维或根因分析相关日志数据；
- TeleLogsAgent：工具交互和运维 Agent 评价候选。

它们可以帮助构造 Agent 的任务和工具接口，但不能替代 CSI、信道、设备能力和业务 KPI。

## 6. 工具链比较

<a id="s6-1"></a>

### 6.1 Sionna

#### 定位

Sionna 当前本地 README 将其分成三个主要部分：

- Sionna RT：无线传播射线追踪；
- Sionna PHY：链路级无线通信仿真；
- Sionna SYS：基于物理层抽象的系统级仿真。

这使 Sionna 很适合做从传播/信道、物理层到部分系统级的连续实验，也适合与深度学习模型和 PyTorch 工作流结合。

#### 对本项目的价值

- 产生或处理 CSI、路径和传播结果；
- 评价编码、调制、信道编码、检测和链路指标；
- 研究 CSI 过期、噪声、反馈延迟和丢失；
- 将无线仿真与神经模型放在同一 Python 实验流水线中；
- 为 Agent 提供可交互的评估工具。

#### 限制

- 不自动提供模型注册表、版本事务和 Agent；
- 不自动提供完整真实 O-RAN 控制栈；
- RT 场景的几何、材料和标定质量会影响结论；
- PHY、SYS 和 RT 的输入输出不能默认直接拼接；
- 软件版本、GPU、CUDA、PyTorch 和场景文件必须固定。

#### 适合的实验

```text
Agent 选择测试场景/反馈策略
  -> Sionna PHY/RT 工具执行
  -> 返回 NMSE、BLER、吞吐、时延和资源摘要
  -> UE Runtime 检查本地预算
  -> Agent 选择继续、切换或回退
```

<a id="s6-2"></a>

### 6.2 QuaDRiGa

> 2026-10-25 补充核验：本次 CSI 压缩反馈的数据主线与具体 API 见[数据方案](CSI压缩反馈数据生成方案.md)。DeepMIMO v4 已支持 Doppler、显式时间轴及动态场景，下面按“各自强项”比较，不应读成 DeepMIMO 只支持静态数据。来源见[官方动态教程](https://www.deepmimo.net/docs/applications/5_dynamic_rt.html)。

#### 定位

QuaDRiGa 是几何基础的随机信道建模工具，适合生成具有空间、时间、频率相关性的无线信道，尤其适合研究移动性、轨迹、阵列和多用户信道变化。

#### 对本项目的价值

- 生成时间相关 CSI；
- 模拟移动 UE、速度和轨迹；
- 研究 CSI 过期、预测失败和反馈时延；
- 比单纯独立随机样本更接近连续运动中的信道变化；
- 构造不同场景和参数下的鲁棒性测试。

#### 限制

- 它不是完整 PHY 链路仿真器；
- 它不是网络级调度器或 O-RAN 仿真器；
- 它不包含模型发布、设备资源和 Agent 事务；
- 随机信道仍是模型生成，不是实测传播；
- 需要将信道输出接到自己的 PHY、CSI 编解码或系统级仿真器。

#### 与 DeepMIMO 的差异

| 维度 | QuaDRiGa | DeepMIMO |
|---|---|---|
| 主要角色 | 参数化/时间相关信道模型 | 射线追踪场景到数据集的生成接口 |
| 强项 | 移动性、空间/时间相关性、随机化 | 场景化、用户位置、射线追踪数据和 ML 数据组织 |
| 典型数据 | 连续轨迹上的信道系数 | 指定场景的信道/路径样本；v4 亦支持 Doppler 与动态场景 |
| 适合研究 | 过期、预测、反馈时序和动态鲁棒性 | 场景泛化、空间划分和固定模型评估 |
| 不能替代 | 真实测量和完整链路 | 真实测量和在线环境 |

第一版不需要同时使用 QuaDRiGa 和 DeepMIMO。若研究重点是模型发布和事务，先用 DeepMIMO 或固定 CsiNet 数据；若研究重点是 CSI 时效和反馈控制，再加入 QuaDRiGa。

<a id="s6-3"></a>

### 6.3 DeepMIMO

DeepMIMO 适合把场景、用户区域、阵列、频率和采样参数变成可重复的数据生成流程。它是当前最适合第一版 CSI 场景扩展的工具之一，但必须注意：

- 场景生成参数决定数据分布；
- 空间相邻点不能随机分到训练和测试两侧；
- 同一射线追踪场景的不同设置可能并不构成真正独立的测试环境；
- 预生成数据不能自动重算 Agent 动作后的网络状态；
- 使用它不能直接声称真实设备泛化。

建议按**场景区域或轨迹组**划分，而不是按单个 CSI 样本随机切分。

<a id="s6-4"></a>

### 6.4 MATLAB 5G Toolbox 和 Wireless Toolbox

MATLAB 工具链适合做标准参数、NR 波形、信道、链路级和系统级的快速验证，尤其适用于：

- 3GPP NR 波形和参数；
- TDL/CDL 等信道模型；
- CSI-RS、反馈和链路流程原型；
- 参考实现和结果交叉检查；
- 与既有 MATLAB 无线算法代码衔接。

限制是：

- 商业许可和版本依赖；
- Agent、模型注册和端网事务仍需自己实现；
- 不应把工具箱生成结果直接称作实测；
- MATLAB 与 Python、Sionna、ns-3 之间需要明确接口和单位转换。

如果团队已经有 MATLAB 代码，它适合作为参考实现或交叉验证工具；如果希望全部实验开源和自动化，Sionna/Python 链路更容易形成可复现实验包。

<a id="s6-5"></a>

### 6.5 5G-LENA

5G-LENA 是基于 ns-3 的 NR 系统级仿真模块，适合评价：

- 小区和多 UE；
- 调度、负载、移动性和资源分配；
- 吞吐量、时延、丢包、可靠性和业务 KPI；
- 网络侧策略对业务结果的影响。

它不适合直接承担：

- 高保真的神经 CSI 编解码模型；
- 复杂射线追踪传播细节；
- 真实 UE 端推理功耗；
- 完整 O-RAN 商用接口。

5G-LENA 最适合作为 Sionna/DeepMIMO/CsiNet 输出之后的系统级验证层。需要自己定义模型动作如何影响 CSI、反馈开销、链路预算或调度状态。

<a id="s6-6"></a>

### 6.6 ns-3 O-RAN 模块

本地 `ns3-oran` README 显示，它提供了 Near-RT RIC 模型、报告和命令仓库、Logic Module、冲突缓解 API、节点报告、组件激活/停用，以及 ONNX Runtime/PyTorch 集成等功能。

对本项目的价值：

- 模拟网络侧 Agent 或 xApp 的调用位置；
- 记录报告、命令、逻辑模块和冲突处理；
- 研究网络侧模型或配置动作如何影响后续状态；
- 把模型生命周期控制面接入网络级仿真。

限制：

- 功能建模不等于真实 E2 协议实现；
- README 中的示例不能自动推断为完整 5G NR O-RAN 支持；
- 与 5G-LENA、ns-3 版本、PyTorch 和 ONNX Runtime 有依赖；
- UE 本地 Runtime 和模型配对事务仍需自行扩展。

如果论文核心是“端网模型生命周期 Agent”，ns-3 O-RAN 可以作为网络控制层，但不能单独作为完整的无线数据来源。

<a id="s6-7"></a>

### 6.7 OpenAirInterface（OAI）

OAI 是软件 RAN 栈，支持 4G/5G 研究、仿真、原型和 COTS 硬件部署。其仓库包含 gNB、UE、协议栈、RF simulator 和 E2 相关代码路径。

对本项目的价值：

- 软件 UE/gNB 行为和日志；
- RF simulator 下的端到端协议集成；
- 真实接口、配置、启动、停止和故障记录；
- 后续接 SDR 做硬件在环或授权实测；
- 验证 Agent 不在时隙级实时路径上时，能否安全参与慢速管理。

限制：

- 构建和配置成本高；
- 版本、内核、网卡、USRP、射频前端和核心网依赖明显；
- RF simulator 不是现场无线传播；
- 运行日志和软件行为不等于真实射频性能；
- 模型发布和 CSI 神经编解码接口需要自行接入。

OAI 更适合第二阶段或第三阶段，不建议作为第一步的唯一实验环境。

<a id="s6-8"></a>

### 6.8 srsRAN

srsRAN 适合构建开放软件 RAN、软件 UE/gNB 和 SDR/仿真相关实验。它与 OAI 类似，可以提供软件协议栈和硬件在环路径，但具体功能、版本和设备支持必须以当前官方文档为准。

它适合的研究问题：

- 软件 RAN 侧的模型部署和控制接口；
- UE/gNB 版本不一致和配置变更；
- 端到端吞吐、时延和连接稳定性；
- 与 SDR 的硬件在环测试。

它不自动解决：

- CSI 神经模型的训练和部署；
- BS/UE 双 Agent 协议；
- 模型证据和回退评价；
- 实际运营商网络数据获取。

OAI 和 srsRAN 不建议在第一篇论文中同时做主平台。应根据团队熟悉度、设备和已有代码选择一个。

<a id="s6-9"></a>

### 6.9 FlexRIC 和 O-RAN 软件集成

FlexRIC、ns-3 O-RAN 和 OAI 组合适合做 RIC/xApp 或网络控制面的实验，但它们的接口、版本和运行方式不是同一个统一平台。使用时需要固定：

- ns-3 或 OAI 版本；
- E2/RIC 适配方式；
- 报告和控制动作的字段；
- xApp/rApp 的调用时序；
- 统计指标和时间戳；
- 失败、重试和组件重启方式。

不要因为仓库名称中有 O-RAN 就直接写成“标准 O-RAN 测试床”。需要说明是仿真模型、软件栈集成还是硬件测试。
