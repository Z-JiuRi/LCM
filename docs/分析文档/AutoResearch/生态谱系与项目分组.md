## 22. 2026 年 Autoresearch 生态全景：从实验循环到自主研究组织（2026-10-22 增订）

> **本章对[第 21 章](概念边界与详细对照.md#s21)的重要修正**：21.5 节描述的是 **Karpathy 2026 年 3 月发布的特定实验范例**，不能代表所有 autoresearch。如今有多条并行发展路线：通用代码与系统优化、ML 开放式实验、长期科研运行、科研论文全链路、群体协作、自我改进、可信验证和科研判断评测。它们在目标函数、搜索空间、实验协议、时间尺度及科学有效性上并不等价。本章优先阅读**项目原始 README / 代码协议、论文摘要与作者的一手技术博客**；没有实际运行或复现仓库，案例数值均为来源方报告。**截至 2026-10-22**。
>
> **检索定义**：宽义 `autoresearch` 还会指文献搜索和科研写作工具，本章另设“文献探索/科学判断”类；不将只生成报告、不执行或验证实验的系统误称为代码优化型 autoresearch。同名的 `AutoResearch` 论文与 Karpathy 仓库可能**没有直接继承关系**。

<a id="s22-1"></a>

### 22.1 核心结论与研究谱系

**观点 1：autoresearch 不是某一套框架，而是“以可检验反馈推动研究活动迭代”的设计模式与不断扩展的系统家族。** 可将研究目标抽象为 `proposal → executable intervention → observation → verification → memory → new proposal`。Karpathy 的原版正是其中最简的可执行实例；oh-my-pi/pi-autoresearch 将其工程化成长期实验协议；ARIS、AutoResearchClaw、NanoResearch 将它拓宽到科研 workflow；Agora/CORAL/SwarmResearch 将主体由单 Agent 变成研究群体；AIDE² 把 agent harness 本身变成研究对象。[A01][A02][A03][A05][A07][A08][A09][A10][A13]

**观点 2：今天“代码修改—五分钟训练—比较单一分数”只能描述某个基线，不能定义研究前沿。** 例如：

- pi-autoresearch 支持测试耗时、bundle 体积、训练、Lighthouse 等任意可测指标，包含持久记录、质量关卡、可视化、上下文压缩后续跑；oh-my-pi 使用固定 `autoresearch.sh`、结构化 METRIC/ASI、实验分段、质量标记与偏离审计。[A02][A03]
- AutoResearchClaw 有 8 个 phase / 23 个 stage、文献与引用核查、实验迭代、科研决定 PIVOT/REFINE/PROCEED、论文生成及一定程度的经验复用；ARIS 采用跨模型异议审查、证据到论文主张的对照账本。[A05][A06][A07]
- Agora 将研究贡献记录成 Git 中的有向无环图，提供独立验证与跨 Agent 复用；AIDE² 的外层循环持续改写内层研究 Agent 本身的搜索策略/记忆机制。[A14][A21]
- 2026-10-15 的 Athanor 在多节点 GPU 环境中测试 **自主后训练**；SciΠvot 则专门问：Agent 能否识别何时应纠正一条科研思路？[A29][A30]

**观点 3：自主性、实验搜索能力、科研真实性是三条独立坐标轴。** 无人干预时间长，不代表假设原创；分数进步，不代表可以外推到未见数据；论文写得像真论文，不代表实验做过。对照 AutoResearchEval、Heuresis、Reward Hacking、Into the Unknown 的实证，当前技术的主要弱点落在 **评估器隔离、验证数据自适应复用、研究决策、原创性、因果解释和科学证据完整性**。[A17][A18][A23][A31]

<a id="s22-1-1"></a>

#### 22.1.1 六种“autoresearch”不要混淆

| 类型 | 目标对象 | 代表 | 反馈信号 | 能力边界 |
|---|---|---|---|---|
| R1 受控优化环 | 固定代码/参数范围 | Karpathy autoresearch | validation bpb | 主要是局部可执行经验搜索 |
| R2 通用优化 Harness | 任意可测程序表现 | oh-my-pi、pi-autoresearch、uditgoenka | 自定义指标 + tests + 运行日志 | 指标定义/保护仍需工程设计 |
| R3 开放式 ML 研究 Agent | 模型、特征、训练算法、数据策略 | AIDE、Heuresis、Athanor | 多实验、开发集和隐藏集 | 搜索空间开放，但科学判断仍不可靠 |
| R4 端到端 AI Scientist | 文献、想法、实验、论文 | ARIS、AutoResearchClaw、NanoResearch、FARS | 实验 + 审稿/审计 | 发表级可靠性不可由自动产出保证 |
| R5 群体/自进化系统 | 研究群体共享的代码/知识，甚至 Agent 本身 | CORAL、Agora、SwarmResearch、AIDE² | 群体基准、迁移、独立复核 | 需要隔离、成本会计与研究治理 |
| R6 可信科研与评测 | 实验判断、真实性、长期泛化 | AutoResearchEval、SciΠvot、Autoresearch Bench | 隐藏测试、过程标注、专家纠错 | 评估维度不能互换 |

> 分类是本报告的**分析框架**，不是社区已统一采纳的官方命名。项目可横跨多个类别，例如 ARIS 同时覆盖 R4 与 R6 的部分能力。

### 22.3 项目生态：按技术结构分组，而非按 GitHub Star 排名

<a id="s22-3-1"></a>

#### 22.3.1 通用实验优化和编码 Agent 宿主

| 项目 | 核心实现与值得看代码 | 区别于 Karpathy 原版 | 项目入口 | 证据类型 |
|---|---|---|---|---|
| Karpathy autoresearch | `program.md` 指导 `train.py` 实验；固定训练预算与 loss 度量 | 最小模型训练范例，不是通用实验平台 | [仓库](https://github.com/karpathy/autoresearch) | 官方 README [A01] |
| **oh-my-pi autoresearch** | 内置 prompt、`init_experiment`/`run_experiment`/`log_experiment`/`update_notes`；固定 `autoresearch.sh`；METRIC/ASI | 多指标元数据、segment、持久提示词、flag_runs、改动范围审计 | [源码协议](https://github.com/can1357/oh-my-pi/blob/main/packages/coding-agent/src/autoresearch/prompt.md) | 官方源码 [A02] |
| **pi-autoresearch** (davebcn87) | pi extension + `.auto/prompt.md`、`measure.sh`、`log.jsonl`、可选 `checks.sh` | 通用优化对象、dashboard、MAD 噪声提示、上下文压缩续跑、分支 review | [仓库](https://github.com/davebcn87/pi-autoresearch) | 官方 README [A03] |
| **uditgoenka/autoresearch** | Claude Code/OpenCode/Codex 的 skill/orchestrator，包含 plan/debug/fix/security/ship/learn/reason 等 | 将目标优化扩展到迭代调试、安全审核与交付流程；某些子命令不再是标准数值优化 | [仓库](https://github.com/uditgoenka/autoresearch) | 官方 README [A04] |
| drivelineresearch/autoresearch-claude-code | 面向 Claude Code 的通用实验循环及棒球生物力学案例 | port + 领域任务适配 | [仓库](https://github.com/drivelineresearch/autoresearch-claude-code) | 社区索引 [A33] |
| leo-lilinxiao/codex-autoresearch | Codex-native skill；resume、lessons、可选并行 | 宿主深度适配与断点恢复 | [仓库](https://github.com/leo-lilinxiao/codex-autoresearch) | 社区索引 [A33] |
| junjunjunbong/research-loop | 决策性 runner、隔离 worktree、计划哈希、追加日志 | 侧重授权边界和可核验的实验账本 | [仓库](https://github.com/junjunjunbong/research-loop) | 社区索引 [A33] |
| supratikpm/gemini-autoresearch | Gemini CLI/Antigravity；声明使用检索 grounding 与 headless loop | 宿主适配，不应未经测试直接视为性能领先 | [仓库](https://github.com/supratikpm/gemini-autoresearch) | 社区索引 [A33] |
| greyhaven-ai/autocontext | agent 改进控制层、持久经验、分阶段验证、distillation | 从“调应用代码”转向“调 agent 行为” | [仓库](https://github.com/greyhaven-ai/autocontext) | 社区索引 [A33] |
| RightNow-AI/autokernel | 生成并测量 Triton GPU kernels | CUDA/Triton 代码优化；必须配合严格正确性测试 | [仓库](https://github.com/RightNow-AI/autokernel) | 官方仓库 [A39] |

**特别需要澄清：oh-my-pi 的内建 autoresearch ≠ davebcn87 的 `pi-autoresearch` 外部扩展。** 两者协议不完全相同：前者在 prompt 中规定 `bash autoresearch.sh` 为固定执行入口、显式支持 `new_segment`/`update_notes`；后者主要以 `.auto/measure.sh`、`log.jsonl` 和 pi extension/dashboard 构造实验循环。若部署选型或实现复现，必须按实际项目与 commit 分别核对。[A02][A03]

#### 22.3.2 科学研究全流程与研究工作空间

| 项目 | 主要研究单元 | 显著实现 | 应审慎解读的地方 | 原始来源 |
|---|---|---|---|---|
| **AutoResearchClaw** | 题目→文献→假设→实验→评审→LaTeX | 23 stages / 8 phases；pivot/refine/continue；引用核查；可选人类审批 | “可生成论文”不是“论文必然可信或可发表” | [A05] |
| **ARIS (Auto-Research-in-Sleep)** | 可组合科研技能 + 多模型交叉复核 | 执行模型/审核模型、Research Wiki、claim ledger、完整性检查、GPU 实验与反驳 | README 中技能总数和模型支持随版本变化，审计并非独立真值证明 | [A06][A07] |
| **NanoResearch (OpenRaiser)** | 端到端研究执行工作流 | 文献 API、实验代码、本地/SLURM GPU、日志、画图、LaTeX、恢复 | “真实实验输出”是官方功能声称，本报告未重跑验证 | [A08] |
| **CORAL** | 共享 grader 下的 Agent 研究组织 | 隔离 workspace、知识共享、多岛屿/迁移、容器保护评分器 | 非所有 CORAL 任务都属于科学发现 | [A09] |
| **FARS** | 大规模自动 AI 研究产物 | 跨主题的多阶段 worker 和共享工作区；公开全部中间工件 | 论文数量反映产出规模，不等于科学质量/接受率 | [A16] |
| **AutoResearch（execution-grounded）** | 文献+可运行代码+引用核查 | sandbox、自动修复、claim-support 审计、结构化 LaTeX | 作者明确称研究助手，**不声称已成为自主科学家** | [A38] |
| **AutoResearch（Insight In, Hallucination Out）** | idea generation + idea execution | 研究信号融合、跨模型 review、证据门控 | 与 Karpathy 同名，但系统定位不同 | [A37] |
| **NanoResearch（OpenRaiser）以外的 NanoResearch 同名论文** | 通常是记忆/技能演化研究 | 需以作者和仓库区分 | 名字相同不应合并成果 | [A08][A33] |

<a id="s22-3-3"></a>

#### 22.3.3 并行搜索、经验累积与自我改进

| 系统 | 搜索/协作机制 | 特有研究问题 | 来源 |
|---|---|---|---|
| **SwarmResearch** | Shepherd 有全局状态；多个 Search Agents 在不同 Git 分支局部探索 | 避免单轨迹陷入“只做微调”与研究方向坍缩 | [A13] |
| **Agora** | Git DAG 将 hypothesis、result、verification、report 连接为群体公共记忆 | 无中心规划也能合并研究贡献吗？如何跨 Agent 验证？ | [A14] |
| **Heuresis** | Greedy、MAP-Elites、Go-Explore、Islands、Curiosity、Omni 六种策略 | 高分、搜索多样性和真正新颖性是否可兼得？ | [A18] |
| **AIDE²** | 外层修改研究 Agent 的 harness，内层 Agent 改业务代码 | 自我改进能否跨任务迁移、减少作弊？ | [A21] |
| **CORAL multi-island** | 隔离研究群体与策略迁移 | 多研究分支如何通信而不泄露 private grader？ | [A09] |
| **AutoMIP** | idea pool + algorithm tree | MILP/MINLP 领域中防止尚未验证的假设被早早遗忘 | [A28] |
| **World Model RL** | 在 agent 后训练中以世界模型近似昂贵执行环境 | 用偏差/噪声校正减少 rollout 的真实执行成本 | [A24] |

<a id="s22-3-4"></a>

#### 22.3.4 追踪整个生态最有价值的两个索引

- **webfuse-com/awesome-autoresearch**：按通用后代、科学研究系统、硬件适配、领域改造、评测与案例分组；适合发现仓库，但集合性描述必须回到原仓库确认。[A33]
- **WecoAI/awesome-autoresearch**：突出真实优化轨迹，收录 Liquid、GPU kernels、语音 Agent prompt、网球 XGBoost、滚动古卷、地球系统、模型自我改进等案例；性能数字大多仍属于作者报告/平台整理，不是统一 benchmark。[A12]
